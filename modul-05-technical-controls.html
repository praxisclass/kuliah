Bagian 02

Network Segmentation

Membagi jaringan menjadi segmen-segmen kecil untuk improve security dan performance.

Network segmentation adalah praktik membagi jaringan menjadi segmen-segmen yang lebih kecil, masing-masing berfungsi sebagai sub-network terpisah. Tujuannya: improve security (limit blast radius, contain breach), improve performance (reduce broadcast domain), dan improve compliance (isolate PCI DSS environment).

3 Types of Network Segmentation
Gambar 2. 3 jenis network segmentation — Physical (hardware), Logical (VLAN), Virtualized (SDN/micro-segmentation).
VLAN Best Practice: Sebuah VLAN dapat unite network devices ke dalam independent logical unit tanpa mempertimbangkan physical locations. Setiap VLAN dianggap independent logical unit. Inter-VLAN communication harus melalui firewall/router dengan ACL — bukan direct routing. Ini memungkinkan inspection & filtering traffic antar segment.
Bagian 03

Demilitarized Zone (DMZ)

Small network yang ditempatkan antara internal network dan external network (Internet).

DMZ adalah small network yang ditempatkan antara internal network yang terpercaya dan external network yang tidak terpercaya (Internet). DMZ berisi server yang perlu dapat diakses dari Internet — seperti web server, email server, FTP server, dan DNS server. Jika attacker berhasil mengakses DMZ host, hanya informasi di host tersebut yang terkompromi — internal network tetap aman.

Bagian 04

Firewalls — Types & Roles

Hardware, software, host-based, network-based — dan 5 teknologi firewall inti.

Firewall adalah network security system yang monitors dan controls incoming dan outgoing network traffic berdasarkan predetermined security rules. Firewall menetapkan barrier antara trusted internal network dan untrusted external network (Internet). Firewall dapat hardware, software, atau keduanya.

🖥
Hardware Firewalls

Standalone devices — dedicated appliance yang di-place di network perimeter. Contoh: Cisco ASA, Fortinet FortiGate, Palo Alto, Check Point. Kelebihan: high throughput, dedicated processing, centralized management. Kekurangan: expensive, requires expertise.

💻
Software Firewalls

Installed di OS — contoh: iptables, UFW (Linux), Windows Defender Firewall. Kelebihan: flexible, low cost, granular per-host control. Kekurangan: consume host resources, per-host management overhead.

📱
Host-based Firewalls

Software firewall di individual host. Microsoft Firewall (Windows), iptables, UFW. Different levels of traffic filtering per host. Use case: endpoint protection, defense-in-depth layer per server.

🌐
Network-based Firewalls

Protect entire network segment. Process traffic di network layer. Use case: perimeter defense, inter-VLAN filtering. Biasanya hardware appliance di gateway/perimeter.

4.1 One-Box Firewalls

One-box firewalls adalah single device yang menggabungkan multiple security functions: firewall, VPN, IDS/IPS, antivirus, web filtering, anti-spam. Juga dikenal sebagai UTM (Unified Threat Management) atau NGFW (Next-Generation Firewall). Kelebihan: single management console, cost-effective untuk SME. Kekurangan: single point of failure.

Bagian 05

Firewall Technologies — 5 Types

Dari packet filtering (paling simple) hingga NGFW (paling advanced).

5 Firewall Technologies — Evolution dari Packet Filter ke NGFW
Gambar 4. 5 firewall technologies — Packet Filtering (simple/fast) → Circuit-Level → App Proxy → VPN → NGFW (comprehensive/DPI).

5.1 Detail: Packet Filtering Firewall

Packet filtering examines setiap packet header dan mengizinkan atau menolak berdasarkan ACL (Access Control List) rules. Rules memeriksa: source IP, destination IP, source port, destination port, protocol (TCP/UDP/ICMP). Packet filtering bekerja di Layer 3-4 OSI — tidak inspect payload. Stateless: setiap packet dievaluasi independen, tidak ada session tracking.

✓
Advantages

• Fast — minimal processing per packet
• Low latency, high throughput
• Inexpensive — simple rule set
• Transparent — no client configuration
• Can be implemented di router (ACL)

−
Disadvantages

• No state tracking — can't detect session hijacking
• No payload inspection — malware passes through
• Vulnerable to IP spoofing
• Can't handle complex protocols (FTP, SIP)
• Difficult to manage complex rule sets

5.2 Stateful Inspection Firewall

Stateful inspection (juga disebut stateful packet inspection) adalah evolusi dari packet filtering yang tracks state of network connections — TCP handshake, session establishment, data transfer, session teardown. Firewall memaintain state table yang mencatat active connections. Hanya packets yang match active state table entry yang diizinkan. Ini mencegah unauthorized traffic yang tidak part of established session.

Bagian 06

Next-Generation Firewall (NGFW)

Third-generation firewall — traditional FW + application awareness + IPS + threat intelligence.

NGFW adalah third-generation network security device yang menyediakan traditional firewall capabilities plus advanced features. Selain traditional firewall, NGFW technology memiliki kemampuan: application awareness (identify apps regardless of port/protocol), integrated IPS, threat intelligence feeds, SSL decryption/inspection, dan user identity tracking.

🔍
Deep Packet Inspection (DPI)

Inspect tidak hanya header tapi payload content. Dapat identify application, detect malware signature, block data exfiltration. Trade-off: CPU intensive, latency increase.

📱
Application Identification (App-ID)

Identify application regardless of port/protocol. Misal: Facebook di port 443 tetap terdeteksi sebagai Facebook, bukan "HTTPS". Enable policy per application.

👤
User Identity (User-ID)

Map IP address ke username/identity. Enable policy per user atau group. "Alice can access Facebook but Bob cannot" — regardless of device.

🛡
Integrated IPS & AV

NGFW come as complete packages with antivirus, anti-malware, anti-spam, URL filtering. Tidak perlu separate appliance. Single management console untuk semua.

☁
Cloud Threat Intelligence

Real-time threat feeds dari cloud — update signature & IOCs (Indicators of Compromise) setiap menit. Block zero-day yang belum ada di local signature.

🔓
SSL Decryption

Decrypt SSL/TLS traffic untuk inspection, lalu re-encrypt. 70%+ traffic adalah encrypted — tanpa decryption, firewall buta terhadap malware di HTTPS.

NGFW Examples: Palo Alto Networks (PA-Series), Fortinet (FortiGate), Cisco (Firepower / Secure Firewall), Check Point (Quantum / Maestro), SonicWall (NSa), Sophos (XGS). Pasar NGFW global diperkirakan $6+ milyar di 2025 — semua enterprise punya minimal 1.
Bagian 07

IDS / IPS — Intrusion Detection & Prevention

IDS detects, IPS prevents — dua sistem complementer untuk network security.

IDS (Intrusion Detection System) memantau network traffic untuk suspicious activity dan mengirim alert saat threat terdeteksi. IPS (Intrusion Prevention System) melangkah lebih jauh — tidak hanya mendeteksi tapi juga mengambil action untuk block atau prevent threat. IDS bersifat passive (detect & alert), IPS bersifat active (detect & block).

IDS vs IPS — Detection vs Prevention
Gambar 5. IDS (passive, detect & alert) vs IPS (active, detect & block). Banyak organisasi gunakan keduanya.

7.1 2 Detection Methods

📝
Signature-based Detection

Network traffic dibandingkan dengan database of known attack signatures (patterns). Mirip antivirus — setiap attack punya unique pattern. Kelebihan: low false positive, fast detection untuk known attacks. Kekurangan: cannot detect zero-day atau unknown attacks. Examples: Snort, Suricata signatures.

📊
Anomaly-based Detection

Uses statistical techniques untuk establish baseline normal behavior, then detect deviations. Kelebihan: can detect unknown/zero-day attacks. Kekurangan: high false positive rate, requires tuning period. Modern: ML/AI untuk improve accuracy.

Bagian 08

IDS Types — NIDS, HIDS, Hybrid

3 jenis IDS berdasarkan placement: network-based, host-based, dan hybrid.

N
NIDS — Network IDS

Memonitor traffic untuk specific segment atau device. Ditempatkan di boundaries antara networks, di belakang perimeter firewalls, routers, VPN. Kelebihan: protect multiple hosts dari single location, tidak consume host resources. Kekurangan: cannot inspect encrypted traffic, blind ke host-level activity. Examples: Snort, Suricata, Zeek (Bro).

H
HIDS — Host IDS

Diinstal di specific host, monitor, detect, dan respond ke suspicious activity on that host. Monitor: file system changes, registry, log files, system calls, network connections. Kelebihan: detect host-level attacks (malware, privilege escalation), verify attack success. Kekurangan: consume host resources, per-host management. Examples: OSSEC, Wazuh, Tripwire.

H+
Hybrid IDS

Kombinasi NIDS + HIDS. Menggabungkan advantages: low false-positive rate NIDS + anomaly detection HIDS. Detect unknown attacks. Kelebihan: comprehensive coverage. Kekurangan: complex deployment, higher cost. Examples: Security Onion, AlienVault USM.

8.1 IDS Deployment Locations

📍
NIDS Placement

• Behind perimeter firewall (detect what bypasses FW)
• At network boundaries (between VLANs)
• Behind VPN concentrator (monitor remote access)
• In front of critical server farms
• At DMZ boundary

🖥
HIDS Deployment

• Critical servers first (initial deployment)
• Domain controllers, file servers, database servers
• Expand ke all remaining hosts if manageable
• Endpoint workstations (via EDR agent)
• Cloud instances (agent-based)

Bagian 09

Honeypots

Decoy system yang menarik attacker — untuk study, detect, dan divert serangan.

Honeypot adalah decoy system atau network yang dirancang untuk menarik attacker. Tujuannya: (1) distract attacker dari real systems, (2) detect attacks early, (3) gather intelligence tentang TTPs (Tactics, Techniques, Procedures) attacker, dan (4) study malware behavior.

🪤
Low-Interaction Honeypot

Simulate services dan OS — tidak real system. Attacker interact dengan emulated services. Kelebihan: safe (no real system to compromise), low maintenance, easy deploy. Kekurangan: easy to detect by skilled attacker, limited intelligence gathering. Examples: Honeyd, Dionaea.

🍯
High-Interaction Honeypot

Real system dengan real services. Attacker dapat fully interact — install tools, pivot. Kelebihan: rich intelligence, capture real attack TTPs, capture malware samples. Kekurangan: risky (can be used to pivot to real network), high maintenance. Examples: honeynet, Cuckoo sandbox.

🔬
Research Honeypot

Dirancang untuk research dan threat intelligence. Digunakan oleh researchers, academia, security vendors. Goal: understand attacker behavior, discover new TTPs, capture zero-day. Long-term deployment.

🏭
Production Honeypot

Dirancang untuk production environment — detect attacks on organizational network. Goal: early warning system, alert security team saat attacker interacts. Short-term, actionable alerts.

Honeynet: Sebuah network of honeypots — multiple decoy systems yang terhubung. Memberikan environment lebih realistis untuk attacker. Honeypot Project (honeynet.org) — komunitas global yang share threat intelligence dari honeypots. Tools: T-Pot (all-in-one honeypot platform), Canarytokens (thinkst.com — free honeypot tokens).
Bagian 10

Proxy Servers

Intermediary antara client dan server — untuk security, privacy, dan performance.

Proxy server bertindak sebagai intermediary antara client dan server. Client tidak connect langsung ke server — melainkan ke proxy, yang kemudian forward request ke server. Proxy menyediakan: security (filtering, logging), privacy (hide client IP), dan performance (caching, compression).

➡️
Forward Proxy

Client → Proxy → Internet. Hide client identity dari server. Control outbound access (URL filtering, content filtering). Contoh: Squid, corporate web proxy.

⬅️
Reverse Proxy

Internet → Proxy → Internal Server. Hide server identity dari client. Load balancing, SSL termination, WAF (Web Application Firewall). Contoh: Nginx, HAProxy, Cloudflare.

🔓
Open Proxy

Proxy yang accessible oleh siapa pun di Internet. Sering disalahgunakan untuk anonymous browsing, bypass geo-restriction. Risk: dapat menjadi exit node untuk malicious activity.

🌐
Web Proxy / Application Proxy

Proxy yang bekerja di Layer 7 (Application). Inspect HTTP/HTTPS content, filter URLs, block malware downloads. Logging: can understand application-level activity. Authentication: user-level auth.

10.1 Proxy Benefits & Limitations

✓Benefits

  • Good logging — can understand application-level activity
  • Reduce network load — caching frequently accessed content
  • User-level authentication — control per user, not just IP
  • Protection for weak protocols — proxy can add encryption
  • Content filtering — block malware, phishing, inappropriate content
  • Privacy — hide internal IP structure from external

−Limitations

  • Lag behind — new protocols wait until suitable proxy available
  • Requires client/app changes — configure proxy settings
  • Single point of failure — proxy down = no access
  • Performance overhead — additional hop, processing
  • Limited protocol support — each protocol needs separate proxy
  • Encrypted traffic blind spot — unless SSL inspection enabled
Bagian 11

Virtual Private Network (VPN)

Private network constructed using public networks — encrypts traffic, ensures confidentiality.

VPN adalah private network yang dibangun menggunakan public networks seperti Internet. VPN memungkinkan utilization of a public network as a private network. VPN melakukan encryption dari packets yang dikirim over the Internet. VPN combines advantages dari both private dan public networks — security dari private, reachability dari public.

11.1 VPN Security Advantages

🔒
Confidentiality

VPN hides all traffic yang flows through it. Ensures confidentiality via encryption — ISP, attacker, eavesdropper tidak dapat read content.

🛡
Integrity & Authentication

VPN ensures data integrity (no tampering in transit) dan authentication (verifies identity of endpoints). Uses cryptographic protocols: IPsec, SSL/TLS.

11.2 2 Types VPN

🏢
Site-to-Site VPN

Menghubungkan dua atau lebih network (e.g., branch office ke HQ). Transparent ke end users — tidak perlu VPN client. Dibangun antara two VPN gateways (router/firewall). Protokol: IPsec (AH/ESP, tunnel mode).

👤
Remote Access VPN

Menghubungkan individual user ke private network dari remote location. User install VPN client di device. Protokol: SSL/TLS VPN (HTTPS-based), IPsec (IKEv2), L2TP/IPsec, WireGuard (modern).

VPN Protocols Comparison: IPsec — network layer, strong, complex, standard for site-to-site. SSL/TLS VPN — application layer, easy (browser-based), good for remote access. WireGuard — modern, lightweight, fast, secure by design — masa depan VPN. OpenVPN — open-source, SSL/TLS based, highly portable, widely supported.
Bagian 12

SIEM — Security Information & Event Management

Centralized platform untuk collect, analyze, dan correlate security events dari multiple sources.

SIEM adalah centralized platform yang mengumpulkan, menganalisis, dan mengkorelasikan security events dari multiple sources di seluruh organisasi — firewall logs, IDS/IPS alerts, antivirus events, endpoint logs, application logs, authentication logs. SIEM menyediakan real-time analysis dari security alerts generated oleh network hardware dan applications.

📥
Log Collection

Collect logs dari ratusan sumber: firewall, IDS/IPS, servers, endpoints, apps, cloud services, AD. Format: Syslog, CEF, LEEF, JSON, XML. Normalization ke common format.

🔗
Correlation

Correlate events across sources untuk detect complex attacks. Example: "5 failed logins dari IP X + port scan dari IP X = brute force attack." Correlation rules & engine.

📊
Analysis & Dashboards

Real-time dashboards, trend analysis, anomaly detection. Security posture overview. KPIs: MTTR (Mean Time to Respond), alert volume, false positive rate.

🚨
Alerting & Incident Response

Automated alerting berdasarkan correlation rules. Integration dengan SOAR (Security Orchestration, Automation, Response) untuk automated response. Ticket creation, escalation.

📜
Compliance Reporting

Pre-built compliance reports: PCI DSS, HIPAA, SOX, GDPR, ISO 27001. Audit trail untuk regulators. Retention policy per regulation.

🗄
Forensic Analysis

Search historical data untuk investigate incidents. Timeline reconstruction. Evidence untuk legal proceedings. Long-term storage (hot + cold).

SIEM Examples: Splunk Enterprise Security, IBM QRadar, Microsoft Sentinel (cloud-native), Elastic Security, Datadog, LogRhythm, ArcSight, Google Chronicle. Tren: SIEM + SOAR + UEBA (User & Entity Behavior Analytics) = next-gen SOC platform.
Bagian 13

User Behavior Analytics (UBA)

Detect anomalous user behavior menggunakan machine learning dan statistical analysis.

UBA (User Behavior Analytics) — juga disebut UEBA (User & Entity Behavior Analytics) — menggunakan machine learning dan statistical analysis untuk establish baseline normal user behavior dan detect anomalous deviations. UBA tidak menggantikan SIEM — melengkapi SIEM dengan behavioral detection yang dapat menangkap insider threats dan compromised accounts yang tidak terdeteksi oleh traditional signature-based rules.

📊
Baseline Establishment

UBA mempelajari normal behavior setiap user: login time, location, access patterns, data volume, application usage, peer group behavior. Diperlukan 30-90 hari untuk establish reliable baseline.

🚨
Anomaly Detection

Deviation dari baseline = alert. Contoh: user login dari negara berbeda, akses data di luar jam kerja, download volume tidak biasa, akses aplikasi yang tidak pernah diakses sebelumnya.

🤖
ML/AI Models

Machine learning models: supervised (trained dengan labeled data), unsupervised (clustering, peer group analysis), semi-supervised (hybrid). Continuous learning dari feedback.

👤
Insider Threat Detection

UBA excel di insider threat detection — user yang sudah authenticated tapi behaving abnormally. Malicious insider, compromised account, atau careless employee — semua terdeteksi via behavior deviation.

UBA Use Cases: (1) Compromised account detection ( credential theft), (2) Insider threat (data exfiltration by employee), (3) Privilege misuse (admin accessing data outside job scope), (4) Lateral movement detection (attacker pivoting in network), (5) Account takeover (login anomaly). Examples: Exabeam, Securonix, Gurucul, Microsoft Defender for Identity.
Bagian 14

Antivirus & Anti-malware Software

Detect, prevent, dan remove malware — dari signature-based hingga AI-driven EDR.

Antivirus/anti-malware software adalah program yang dirancang untuk detect, prevent, dan remove malicious software (malware) — termasuk virus, worm, trojan, ransomware, spyware, adware, rootkit. Modern antivirus berevolusi menjadi EDR (Endpoint Detection & Response) dan XDR (Extended Detection & Response).

📝
Signature-based

Mendetect malware berdasarkan known signature (pattern). Setiap malware punya unique fingerprint. Kelebihan: fast, accurate untuk known malware. Kekurangan: cannot detect zero-day atau polymorphic malware.

🔍
Heuristic Analysis

Analyze code behavior dan structure untuk detect new/unknown malware. Tidak bergantung pada signature. Dapat detect zero-day. Trade-off: higher false positive rate.

🤖
Behavior-based / AI

Monitor runtime behavior — file execution, network connections, registry changes, system calls. ML models classify sebagai malicious atau benign. Dapat detect fileless malware.

🛡
EDR (Endpoint Detection & Response)

Beyond traditional AV — continuous monitoring, threat hunting, incident response. Collect telemetry dari endpoint, centralize untuk analysis. Examples: CrowdStrike Falcon, Microsoft Defender for Endpoint, SentinelOne.

Antivirus Best Practices: (1) Deploy di semua endpoint (server, workstation, mobile), (2) Enable real-time protection + scheduled scan, (3) Auto-update signature daily, (4) Centralized management console, (5) Integration dengan SIEM untuk alert correlation, (6) Application whitelisting (AppLocker, Carbon Black) sebagai defense-in-depth, (7) Sandbox untuk analyze suspicious files.

15.3 Workflow Praktikum 4 Sesi

Alur Praktikum — 4 Sesi, 20 Langkah, 1 Laporan Akhir
Gambar 6. Workflow 4 sesi praktikum Modul 05 — total 20 langkah hands-on.

15.4 Langkah Praktikum

Sesi 1 — pfSense Firewall Configuration

1
Install pfSense di VM

Download pfSense CE ISO dari pfsense.org. Create VM dengan 3 network interfaces: WAN (external), LAN (internal), OPT1 (DMZ). Boot dari ISO, install ke disk. Set IP: WAN = DHCP, LAN = 192.168.1.1/24, OPT1 = 192.168.2.1/24.

2
Configure VLANs

Di pfSense web interface (https://192.168.1.1): Interfaces → Assignments → VLANs. Buat VLAN 10 (Servers), VLAN 20 (Employees), VLAN 30 (Guest). Assign ke OPT1 interface. Set firewall rules: allow Employees → Servers (specific ports), deny Guest → Servers, allow all → Internet.

3
Setup DMZ

Di OPT1 (DMZ) interface: enable interface, set static IP 192.168.2.1/24. Create firewall rules: (a) WAN → DMZ: allow port 80, 443 (web server), (b) DMZ → LAN: BLOCK ALL, (c) LAN → DMZ: allow all, (d) DMZ → WAN: allow HTTP/HTTPS only.

4
NAT Port Forwarding

Firewall → NAT → Port Forward. Buat rule: WAN port 80 → DMZ 192.168.2.10:80 (web server). WAN port 443 → DMZ 192.168.2.10:443. Test dari Kali VM (external): curl http://<WAN_IP> — harus reach DMZ web server.

5
Attack Simulation & Laporan

Dari Kali VM: nmap <WAN_IP> — hanya port 80, 443 yang open. Coba akses DMZ dari external ke port 22 → blocked. Coba DMZ pivot ke LAN → blocked. Laporan: network diagram, firewall rules table, NAT rules, test results, security analysis.

Sesi 2 — Snort IDS Deployment

1
Install Snort di Ubuntu Server

apt install snort. Saat install, set network range (HOME_NET) = 192.168.1.0/24. Verifikasi: snort -V. Config file: /etc/snort/snort.conf. Rules directory: /etc/snort/rules/.

2
Configure Snort Rules

Edit /etc/snort/rules/local.rules. Tambahkan rules: alert tcp any any -> $HOME_NET 22 (msg:"SSH connection attempt"; sid:100001;), alert tcp any any -> $HOME_NET 445 (msg:"SMB access"; sid:100002;), alert icmp any any -> $HOME_NET any (msg:"Ping detected"; sid:100003;). Test config: snort -T -c /etc/snort/snort.conf.

3
Start Snort & Generate Traffic

Start Snort di monitoring mode: snort -A console -q -c /etc/snort/snort.conf -i eth0. Dari Kali VM: nmap -sS 192.168.1.0/24, nmap -sV 192.168.1.x, ping flood 192.168.1.x. Amati Snort console — harus muncul alerts.

4
Download & Apply Community Rules

Register di snort.org, download community rules. Extract ke /etc/snort/rules/. Update snort.conf include. Restart Snort. Test dengan Metasploit: msfconsole → use auxiliary/scanner/portscan/tcp → set RHOSTS 192.168.1.0/24 → run. Snort harus detect port scan.

5
Alert Analysis & Tuning

Review alerts di /var/log/snort/alert. Identifikasi false positives — tune rules dengan threshold, suppress. Buat laporan: alerts detected, severity, source IP, target, recommendation. Diskusikan: IDS vs IPS — konversi ke IPS dengan iptables integration.

Sesi 3 — VPN Setup (Site-to-Site + Remote Access)

1
Site-to-Site IPsec VPN di pfSense

Di pfSense: VPN → IPsec → Tunnels. Buat Phase 1: key exchange = IKEv2, encryption = AES256-GCM, hash = SHA256, DH group = 14. Phase 2: protocol = ESP, encryption = AES256-GCM. Set remote gateway = IP VM lain. Buat firewall rules: allow IPsec traffic di WAN + LAN.

2
Test Site-to-Site VPN

Konfigurasi pfSense di VM kedua dengan Phase 1/2 yang mirror. Start tunnel. Test: ping dari LAN1 ke LAN2 — harus sukses via tunnel. traceroute — traffic harus via VPN gateway. Wireshark di WAN — traffic harus encrypted (ESP).

3
Remote Access VPN (OpenVPN)

Di pfSense: VPN → OpenVPN → Wizards. Server mode = Remote Access. Protocol = UDP. Port = 1194. Encryption = AES-256-GCM. Certificate authority: create new. Server cert: create new. Tunnel network = 10.8.0.0/24. Local network = 192.168.1.0/24.

4
Client Setup & Test

Download client certificate + OpenVPN config dari pfSense. Install OpenVPN client di Ubuntu/Kali. Import config. Connect. Test: curl http://192.168.1.1 (pfSense web) dari client — harus reach. ifconfig tun0 — tunnel interface up. Wireshark: traffic via tun0 encrypted.

5

15.6 Checklist Evaluasi

Praktikum dinyatakan lulus jika minimal 10 dari 12 kriteria berikut terpenuhi:

  • VLAN 10/20/30 terkonfigurasi dengan firewall rules

Bagian 16

Ringkasan Modul

Rangkuman poin-poin kritis yang telah dibahas dalam Modul 05 Technical Controls.

📋 Yang Telah Dipelajari

  • Network segmentation — 3 types: Physical (hardware barriers), Logical (VLAN/802.1Q), Virtualized (SDN/VXLAN/micro-segmentation). Benefits: limit blast radius, reduce attack surface, compliance isolation.
  • DMZ (Demilitarized Zone) — small network between internal & external. Contains web, email, FTP, DNS servers. Rules: internal+external → DMZ, DMZ → external, DMZ → internal BLOCKED. Single firewall (3 NIC) vs Dual firewall (more secure).
  • Firewall types — Hardware (Cisco ASA, FortiGate), Software (iptables, UFW), Host-based (per endpoint), Network-based (perimeter). One-box = UTM/NGFW.
  • 5 Firewall technologies — Packet Filtering (Layer 3-4, stateless), Circuit-Level Gateway (Layer 5, session), Application Proxy (Layer 7, deep inspection), VPN (encrypted tunnel), NGFW (DPI + App-ID + User-ID + IPS + AV + threat intel).
  • Stateful inspection — tracks connection state, maintains state table, only allows packets matching active sessions. Prevents session hijacking.
  • NGFW — third-gen firewall with DPI, application awareness, user identity, integrated IPS/AV, cloud threat intel, SSL decryption. Examples: Palo Alto, Fortinet, Cisco Firepower.
  • IDS vs IPS — IDS passive (detect & alert), IPS active (detect & block). IDS out-of-band, IPS inline.
  • 2 Detection methods — Signature-based (known patterns, low false positive, can't detect zero-day) & Anomaly-based (baseline deviation, can detect zero-day, high false positive).
  • 3 IDS types — NIDS (network, monitors segment), HIDS (host, monitors individual system), Hybrid (NIDS + HIDS combined).
  • Honeypots — decoy systems: Low-interaction (emulated, safe), High-interaction (real, risky), Research (threat intelligence), Production (early warning). Honeynet = network of honeypots.
  • Proxy servers — Forward (hide client), Reverse (hide server, load balance, WAF), Open (public, risky), Web/Application (Layer 7, content filtering). Benefits: logging, caching, auth, filtering.
  • VPN — private network over public. Site-to-Site (network-to-network, IPsec), Remote Access (user-to-network, SSL/TLS, IPsec, WireGuard). Security: confidentiality, integrity, authentication.
  • SIEM — centralized log collection, correlation, analysis, dashboards, alerting, compliance reporting, forensic analysis. Examples: Splunk, QRadar, Elastic Security, Sentinel.
  • UBA/UEBA — ML-based user behavior baseline & anomaly detection. Use cases: compromised account, insider threat, privilege misuse, lateral movement.
  • Antivirus/Anti-malware — Signature-based, Heuristic, Behavior-based/AI, EDR (endpoint detection & response). Best practice: deploy all endpoints, real-time + scheduled, auto-update, central management, SIEM integration.
  • Praktikum 4 sesi — pfSense firewall (DMZ, VLAN, NAT), Snort IDS (rules, detection), VPN (IPsec site-to-site, OpenVPN remote), Elastic Security SIEM (log ingest, dashboards, detection rules).
Key Takeaway: Technical controls adalah lapisan aktif defense. Network segmentation membatasi blast radius, firewall mengontrol traffic, IDS/IPS mendeteksi dan mencegah intrusi, VPN mengamankan komunikasi, SIEM memberikan visibility centralized, UBA menangkap insider threat, dan antivirus melindungi endpoint. Tidak ada single control yang cukup — defense-in-depth menggabungkan SEMUA technical controls + administrative (Modul 03) + physical (Modul 04) untuk keamanan yang komprehensif. Modul ini melengkapi trilogi Network Security Controls (Administrative → Physical → Technical).
