Bagian 02

Need & Advantages of Network Traffic Monitoring

Mengapa monitoring network traffic adalah essential untuk security operations.

Network traffic monitoring adalah retrospective security approach yang involves monitoring network traffic, analyzing it, dan extracting traffic characteristics yang help in detecting anomalies. Monitoring network traffic memberikan organisation kemampuan untuk detect malicious activity yang mungkin terlewat oleh preventive security controls seperti firewall dan IDS.

🔍
Detect Suspicious Activity

Monitoring memungkinkan detection of suspicious activities yang tidak terdeteksi oleh real-time controls — misal: slow data exfiltration, C2 beaconing, lateral movement.

📊
Baseline Network Behavior

Monitoring membantu establish baseline normal network behavior — sehingga deviations dapat terdeteksi. Tanpa baseline, sulit distinguish normal dari abnormal.

⚡
Incident Response

Saat incident terjadi, traffic capture (PCAP) adalah evidence terbaik untuk forensics. Monitoring menyediakan historical data untuk reconstruct attack timeline.

📈
Performance & Capacity

Monitoring juga memberikan insights tentang network performance — bandwidth usage, latency, packet loss. Help dengan capacity planning.

Bagian 03

Network Traffic Signatures

Set of traffic characteristics yang define type of activity on a network.

Signatures digunakan untuk define the type of activity on a network. Signature adalah set of traffic characteristics seperti source/destination IP, port, protocol, packet size, timing, dan content pattern. Signatures membantu detect malicious traffic entering a network.

2 Types of Traffic Signatures — Normal vs Attack
Gambar 2. 2 types traffic signatures — Normal (expected, allowed) vs Attack (suspicious, investigate).

3.1 Baselining Normal Traffic

Baselining adalah process of establishing normal traffic patterns untuk network. Tanpa baseline, tidak ada reference untuk detect anomalies. Baselining melibatkan: (1) capture traffic untuk periode yang representative (1-4 minggu), (2) analyze patterns — top talkers, peak hours, protocols used, bandwidth usage, (3) document normal ranges, (4) set thresholds untuk alerts. Baseline harus di-update periodically — network berubah seiring waktu.

Bagian 04

4 Categories of Suspicious Traffic Signatures

Reconnaissance, Unauthorized Access, DoS, dan Informational — 4 kategori utama.

🔍
Reconnaissance Traffic

Signatures yang indicate attempt to discover network resources, services, atau vulnerabilities. Contoh: port scan (nmap), vulnerability scan (Nessus), network mapping, OS fingerprinting. Goal attacker: gather information untuk planning attack.

🔓
Unauthorized Access

Signatures yang indicate attempt to gain unauthorized access ke system atau data. Contoh: brute force (SSH, RDP, FTP), password guessing, privilege escalation, login dari unusual location.

💥
Denial of Service (DoS)

Traffic containing signatures yang indicate DoS attempt yang could disrupt service availability. Contoh: SYN flood, UDP flood, ICMP flood, HTTP flood, slowloris, DDoS amplification (DNS/NTP).

ℹ
Informational Traffic

Traffic containing signatures yang may appear suspicious but might not be malicious. Contoh: unusual but legitimate protocol, new service deployment, network configuration change, unusual but authorized access. Requires investigation — could be false positive.

Bagian 05

Attack Signature Analysis Techniques

3 teknik untuk detect attacks: signature recognition, anomaly detection, protocol anomaly.

📝
Signature Recognition

Juga disebut misuse detection. Identify events yang match known attack patterns (signatures). Mirip antivirus — setiap attack punya unique pattern. Kelebihan: low false positive. Kekurangan: cannot detect unknown/zero-day attacks.

📊
Anomaly-based Detection

Depends on observing dan comparing current behavior dengan established baseline. Detects deviations dari normal. Kelebihan: can detect zero-day. Kekurangan: high false positive rate, requires tuning period.

🔌
Protocol Anomaly Detection

Depends on anomalies specific to a protocol. Contoh: HTTP request dengan invalid method, DNS query dengan unusual format, TCP handshake anomaly. Detects protocol misuse dan malformed packets.

Bagian 06

Wireshark for Network Monitoring

Widely used network sniffer untuk packet analysis dan troubleshooting.

Wireshark adalah widely used network sniffer yang dapat digunakan untuk network troubleshooting, investigate security issues, dan analyze protocol behavior. Wireshark mengcapture packets dari network interface dan displays them dengan detailed protocol dissection. Wireshark adalah de facto standard untuk packet analysis — free, open-source, cross-platform.

6.1 Wireshark Components

📊
Packet List Pane

Displays summary setiap packet — number, timestamp, source, destination, protocol, length, info. Color-coded berdasarkan protocol. Click packet untuk see details.

📋
Packet Details Pane

Displays hierarchical protocol dissection dari selected packet. Expand each layer: Ethernet → IP → TCP → HTTP. Shows field values, flags, options.

🔢
Packet Bytes Pane

Displays raw hex + ASCII dump dari selected packet. Lowest level — actual bytes on wire. Useful untuk custom protocol analysis.

🎨
Color Coding

Wireshark colorizes packet list berdasarkan protocol. Default: light blue = TCP, light green = HTTP, light yellow = DNS. Customizable — create rules untuk highlight suspicious traffic.

6.2 Follow TCP Stream

Wireshark displays data dari TCP port dengan feature yang dikenal sebagai "Follow TCP Stream". Feature ini reassembles semua packets dari TCP conversation menjadi single readable stream. Berguna untuk: melihat complete HTTP request/response, FTP commands, Telnet session, email content. Akses: click packet → Analyze → Follow → TCP Stream (atau right-click → Follow → TCP Stream).

Bagian 07

Wireshark Display Filters

Filter traffic by protocol, IP, port, atau custom expression.

Wireshark features display filters yang filter traffic on target network by protocol type, IP address, port number, atau custom expression. Display filters menggunakan syntax yang powerful — dapat combine multiple conditions. Wireshark dapat use multiple filters at a time.

FilterDescriptionExample
ip.addr == X.X.X.XFilter by IP address (source or dest)ip.addr == 192.168.1.1
ip.src == X.X.X.XFilter by source IP onlyip.src == 10.0.0.5
tcp.port == XXFilter by TCP porttcp.port == 443

http.request.method == "POST"HTTP POST requests onlyhttp.request.method == "POST"
dnsShow only DNS trafficdns
tcp.flags.syn == 1TCP SYN packets (connection starts)tcp.flags.syn == 1 && tcp.flags.ack == 0
tcp.flags.reset == 1TCP RST packets (connection resets)tcp.flags.reset == 1

Pro Tip: Combine filters dengan && (AND), || (OR), ! (NOT). Contoh: ip.src == 10.0.0.5 && tcp.port == 443 = traffic dari 10.0.0.5 on port 443. Simpan frequently used filters di Wireshark → Filter Expression Buttons.
Bagian 08

Protocol Traffic Analysis

Monitoring FTP, Telnet, HTTP traffic untuk detect suspicious activity.

📁
FTP Traffic Analysis

Wireshark provides complete information tentang FTP traffic. FTP is insecure — transmits credentials in plaintext. Filter: ftp atau ftp.request.command. Follow TCP Stream untuk see complete FTP session — username, password (plaintext!), files transferred.

💻
Telnet Traffic Analysis

Telnet juga insecure — all traffic plaintext including login credentials. Filter: telnet. Follow TCP Stream untuk see complete session — commands typed, output, passwords. Timely monitoring of Telnet sessions can minimize risk of credential theft.

🌐
HTTP Traffic Analysis

Monitoring HTTP traffic — filter: http. Identify: unencrypted form submissions (passwords in plaintext), suspicious URLs, unusual user-agents, large file downloads. Ensure applications don't send data over HTTP — use HTTPS.

Security Warning: FTP dan Telnet transmit semua data — including passwords — dalam plaintext. Siapa pun yang dapat sniff network traffic dapat read credentials. Replace FTP dengan SFTP/FTPS, Telnet dengan SSH. Jika masih menggunakan FTP/Telnet, monitoring dengan Wireshark adalah critical untuk detect credential exposure.
Bagian 09

Network Sniffers

Command-line dan GUI tools untuk packet capture dan analysis.

⌨
tcpdump

Command-line network analyzer / packet sniffer. Security professionals use tcpdump untuk capture dan analyze traffic di servers tanpa GUI. Lightweight — minimal resource usage. Output dapat di-save ke PCAP file untuk analysis di Wireshark. tcpdump.org

📊
Wireshark (GUI)

Full-featured GUI packet analyzer. Visual dissection, color coding, follow streams, display filters, statistics. De facto standard untuk packet analysis. Dapat read PCAP files dari tcpdump. Cross-platform: Windows, Linux, macOS.

9.1 tcpdump Common Commands

CommandDescription
tcpdump -i eth0Capture on interface eth0
tcpdump -i eth0 -w capture.pcapCapture to PCAP file
tcpdump -i eth0 port 80Capture only port 80 (HTTP)
tcpdump -i eth0 host 192.168.1.1Capture traffic to/from specific host
tcpdump -i eth0 -c 100Capture first 100 packets then stop
tcpdump -r capture.pcapRead from saved PCAP file
tcpdump -i eth0 -nn -vvVerbose output, no DNS resolution
Bagian 10

Network Monitoring Tools

Comprehensive tools untuk continuous network monitoring — SNMP, NetFlow, SIEM integration.

☀
SolarWinds NPM

Network Performance Monitor — comprehensive network monitoring. SNMP-based, NetFlow analysis, custom alerts, dashboards. Enterprise-grade — widely used di large organizations.

📊
Capsa Free

Free network analyzer — packet capture, protocol analysis, network diagnostics. Real-time monitoring, 24/7 packet capture. Good untuk small networks dan learning.

📡
Monitis

Cloud-based network monitoring solution. Monitor network devices, servers, applications from cloud dashboard. Alert via email/SMS.

🔧
Nagios

Open-source network monitoring. Monitor network services (HTTP, FTP, SSH, SMTP), host resources (CPU, disk, memory). Plugin ecosystem. Industry standard untuk open-source monitoring.

10.1 Monitoring Protocols & Technologies

📡
SNMP Polling

Simple Network Management Protocol — query network devices untuk status (CPU, memory, bandwidth, interface status). SNMP v3 = encrypted. Windows Management Instrumentation (WMI) untuk Windows.

🌊
NetFlow / sFlow

NetFlow (Cisco), IPFIX (standard), jFlow (Juniper), sFlow (industry) — flow-based monitoring. Records source/dest, bytes, packets, duration. Not packet content — metadata only.

SIEM Integration: Network monitoring tools harus integrate dengan SIEM (Modul 05). NetFlow data + SIEM = detect data exfiltration, C2 beaconing, lateral movement. Wireshark PCAP + SIEM = deep-dive forensics. Monitoring + SIEM + DLP = comprehensive visibility.

tcpdump CLI

11.3 Workflow Praktikum 4 Sesi

Alur Praktikum — 4 Sesi, 20 Langkah, 1 Laporan Akhir
Gambar 4. Workflow 4 sesi praktikum Modul 12 (FINAL) — total 20 langkah hands-on.

11.4 Langkah Praktikum

Sesi 1 — Wireshark Packet Capture & Analysis

1
Install & Start Wireshark

Install Wireshark di Kali Linux: apt install wireshark. Launch: wireshark &. Pilih network interface (eth0 atau wlan0). Klik "Start capturing packets". Browse beberapa websites sambil capture berjalan.

2
Apply Display Filters

Stop capture setelah 1-2 menit. Apply filters: http (only HTTP), dns (only DNS), tcp.port == 443 (HTTPS), ip.addr == 8.8.8.8 (Google DNS). Combine: http && ip.addr == 192.168.1.1. Screenshot setiap filter result.

3
Follow TCP Stream

Pilih HTTP packet → right-click → Follow → TCP Stream. Wireshark shows complete HTTP request + response dalam readable format. Identifikasi: HTTP method (GET/POST), headers, response code (200, 404), body content. Screenshot TCP stream.

4
Packet Details Analysis

Pilih satu packet. Expand di Packet Details Pane: Ethernet II → Internet Protocol → Transmission Control Protocol → Hypertext Transfer Protocol. Document: source MAC, dest MAC, source IP, dest IP, TTL, TCP flags, seq/ack numbers, HTTP method, host header.

5
Color Rules & Laporan

Create custom color rule: Edit → Preferences → Coloring Rules. Add rule: tcp.flags.reset == 1 → red background (highlight RST). Capture traffic sambil run nmap scan — RST packets highlighted. Laporan: capture screenshots, filter examples, TCP stream, packet details, color rules.

Sesi 2 — tcpdump Command-Line Capture

1
Basic tcpdump Capture

Di Ubuntu VM: tcpdump -i eth0 — live capture ke console. Press Ctrl+C untuk stop. Lihat: timestamp, protocol, source:port → dest:port, flags, length. tcpdump -i eth0 -c 50 — capture first 50 packets.

2
Save to PCAP File

tcpdump -i eth0 -w capture.pcap -c 500 — capture 500 packets ke file. Verifikasi: ls -la capture.pcap. Read back: tcpdump -r capture.pcap. Transfer PCAP ke Wireshark VM untuk GUI analysis.

3
Filter di tcpdump

By host: tcpdump -i eth0 host 192.168.1.1. By port: tcpdump -i eth0 port 80. By protocol: tcpdump -i eth0 tcp. Exclude: tcpdump -i eth0 not port 22 (exclude SSH). Combine: tcpdump -i eth0 'host 192.168.1.1 and port 80'.

4
Generate Suspicious Traffic

Dari Kali VM: run nmap scan ke Ubuntu: nmap -sS 192.168.1.10. Capture di Ubuntu: tcpdump -i eth0 'host 192.168.1.5 and tcp' -w scan.pcap. Analyze di Wireshark: identify SYN scan pattern (SYN packets tanpa completing handshake).

5
Laporan tcpdump

Laporan: (a) tcpdump commands used, (b) PCAP file analysis di Wireshark, (c) filter examples, (d) nmap scan traffic analysis — identify scan type dari packet pattern, (e) comparison tcpdump vs Wireshark (when to use each).

Sesi 3 — Protocol Traffic Analysis (FTP/Telnet/HTTP)

1
Setup FTP Server & Capture

Di Ubuntu: install vsftpd, create test user. Start Wireshark capture. Dari Kali: ftp 192.168.1.10, login dengan test user, download file, quit. Stop capture. Filter: ftp. Follow TCP Stream — username dan password terlihat plaintext!

2
Telnet Traffic Analysis

Di Ubuntu: install telnetd. Start capture. Dari Kali: telnet 192.168.1.10, login, run beberapa commands (ls, whoami), logout. Stop capture. Filter: telnet. Follow TCP Stream — semua commands dan output plaintext, including password!

3
HTTP Traffic Analysis

Di Ubuntu: install nginx, create login page (HTTP, not HTTPS). Start capture. Dari Kali: browse to http://192.168.1.10/login.html, submit form dengan username/password. Stop capture. Filter: http.request.method == "POST". Follow TCP Stream — form data (credentials) terlihat plaintext!

4
Detect Suspicious Traffic

Generate suspicious traffic: (a) nmap scan: nmap -sS -p 1-1000 192.168.1.10, (b) brute force SSH: hydra -l admin -P rockyou.txt ssh://192.168.1.10. Capture all. Analyze: identify scan pattern (SYN flood), identify brute force (multiple SSH login attempts).

5
Laporan Protocol Analysis

Laporan: (a) FTP capture — plaintext credentials, (b) Telnet capture — plaintext session, (c) HTTP capture — form data exposure, (d) suspicious traffic detection — scan + brute force patterns, (e) recommendation: replace FTP→SFTP, Telnet→SSH, HTTP→HTTPS.

Sesi 4 — Nagios + SNMP Network Monitoring

1
Install Nagios Core

Di Ubuntu: apt install nagios4 nagios-plugins. Set admin password: htpasswd -c /etc/nagios4/htpasswd.users nagiosadmin. Start: systemctl start nagios4 apache2. Access: http://localhost/nagios4.

2
Configure SNMP Monitoring

Install SNMP di target VM: apt install snmpd. Edit /etc/snmp/snmpd.conf — set community string, allow access. Restart: systemctl restart snmpd. Test: snmpwalk -v2c -c public 192.168.1.10 — harus return SNMP data.

3
Add Host ke Nagios

Edit /etc/nagios4/conf.d/hosts.cfg — add target VM sebagai host. Edit services.cfg — add services: check_ping, check_snmp (CPU, memory, disk). Verify config: nagios4 -v /etc/nagios4/nagios.cfg. Restart: systemctl restart nagios4.

4
Set Alerts & Notifications

Configure alerts: (a) host down → email alert, (b) service critical (CPU > 90%) → email, (c) disk space low (< 10%) → warning. Edit contacts.cfg — set email. Test: stop snmpd di target → Nagios should alert "SNMP CRITICAL".

5
Dashboard & Laporan

Review Nagios dashboard: Host Status, Service Status, Alerts. Laporan: (a) Nagios architecture, (b) SNMP configuration, (c) host/service monitoring config, (d) alert test results, (e) dashboard screenshots, (f) recommendation: integrate dengan SIEM untuk centralized alerting.

Bagian 12

Ringkasan Modul (FINAL)

Rangkuman poin-poin kritis yang telah dibahas dalam Modul 12 Network Traffic Monitoring.

📋 Yang Telah Dipelajari

  • Need for network traffic monitoring — detect suspicious activity, baseline network behavior, incident response forensics, performance & capacity planning.
  • Advantages — retrospective security, anomaly detection, historical evidence, compliance audit trail.
  • Network traffic signatures — set of traffic characteristics (IP, port, protocol, timing, content). 2 types: Normal (acceptable) vs Attack (suspicious).
  • Baselining — establish normal traffic patterns (1-4 weeks capture, analyze, document, set thresholds). Without baseline = can't detect anomalies.
  • 4 categories suspicious traffic — Reconnaissance (port/vuln scan), Unauthorized Access (brute force, privilege escalation), DoS (SYN flood, DDoS), Informational (unusual but possibly legitimate).
  • 3 analysis techniques — Signature Recognition (known patterns, low false positive, can't detect zero-day), Anomaly Detection (baseline deviation, detects zero-day, high false positive), Protocol Anomaly (protocol-specific anomalies, malformed packets).
  • 4 detection outcomes — True Positive (attack + alert = ideal), False Positive (no attack + alert = wasted time), True Negative (no attack + no alert = correct), False Negative (attack + no alert = WORST, missed attack).
  • Wireshark — de facto standard packet analyzer. Components: Packet List, Packet Details, Packet Bytes, Color Coding. Features: Follow TCP Stream, display filters, protocol dissection.
  • Wireshark display filters — filter by IP (ip.addr), port (tcp.port), protocol (http, dns), flags (tcp.flags.syn), content (frame contains "password"). Combine with &&, ||, !.
  • Protocol analysis — FTP (insecure, plaintext credentials), Telnet (insecure, plaintext session), HTTP (form data in plaintext). Replace with SFTP, SSH, HTTPS.
  • Network sniffers — tcpdump (CLI, lightweight, save to PCAP), Wireshark (GUI, full-featured, read PCAP). tcpdump untuk servers, Wireshark untuk deep analysis.
  • Monitoring tools — SolarWinds NPM (enterprise), Capsa Free (small network), Monitis (cloud), Nagios (open-source). Protocols: SNMP (device status), NetFlow/sFlow (flow metadata).
  • Praktikum 4 sesi — Wireshark capture & filters, tcpdump CLI, protocol analysis (FTP/Telnet/HTTP), Nagios + SNMP monitoring.
Key Takeaway (FINAL MODULE): Network traffic monitoring adalah mata dari security operations. Tanpa monitoring, organisation buta terhadap apa yang terjadi di jaringan mereka. Wireshark + tcpdump untuk deep-dive packet analysis. Nagios + SNMP untuk continuous device monitoring. SIEM + NetFlow untuk centralized correlation. DLP untuk data movement. Bersama-sama, mereka membentuk comprehensive visibility yang memungkinkan detect, investigate, dan respond ke threats.
