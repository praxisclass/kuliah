Bagian 02

Virtualization Concepts

Software-based virtual representation of resources — dari single physical ke multiple virtual.

Virtualization merujuk pada software-based virtual representation of resources. Virtualization memungkinkan satu physical resource (server, storage, network) muncul sebagai multiple virtual resources. Sebaliknya, multiple physical resources dapat muncul sebagai single virtual resource. Virtualization adalah enabler untuk cloud computing — tanpa virtualization, cloud computing tidak mungkin.

🖥
What is Virtualization?

Virtualization memungkinkan multiple operating systems dan applications berjalan di single physical server secara simultan. Setiap VM (Virtual Machine) bersifat isolated — crash di satu VM tidak mempengaruhi VM lain. Virtualization dipowered oleh hypervisor (VMM — Virtual Machine Monitor).

⚙
Virtualization Components

Host = physical machine yang run hypervisor. Guest = virtual machine yang run di atas hypervisor. Hypervisor/VMM = software yang create, manage, dan monitor VMs. Virtual Resources = vCPU, vRAM, vDisk, vNIC yang allocated ke VMs.

4 Virtualization Approaches

Full, OS-assisted (Para), Hardware-assisted, dan Hybrid Virtualization.

Bagian 04

7 Types of Virtualization

Dari OS virtualization hingga fabric virtualization — setiap type virtualizes resource berbeda.

💻
Operating System Virtualization

Hardware run multiple virtualized OS instances. VM diisolasi satu sama lain. Most common type. Examples: VMware Workstation, VirtualBox, Hyper-V, KVM.

🌐
Network Virtualization

Virtualization network resources — bandwidth, IP addresses, routing, firewalls. SDN (Software-Defined Networking) dan NFV (Network Function Virtualization). Examples: VMware NSX, Cisco ACI, Open vSwitch.

🖥
Server Virtualization

Partition (virtualization) server resources — CPU, RAM, storage, network. Multiple VMs di single physical server. Maximize utilization, reduce hardware cost.

📱
Desktop Virtualization

OS desktop run di server, accessed remotely. VDI (Virtual Desktop Infrastructure). User access virtual desktop dari thin client/any device. Examples: Citrix, VMware Horizon, Microsoft RDS.

💾
Storage Device Virtualization

Virtualization storage devices menggunakan software. Multiple physical storage appear sebagai single virtual storage. Storage pooling, thin provisioning. Examples: vSAN, Ceph, GlusterFS.

📁
File System Virtualization

Virtualization data at level of file system. Multiple file systems accessible via single virtual interface. Examples: NFS, CIFS virtualization, global namespace.

🔌
Fabric Virtualization

Makes virtual devices independent of physical location. Enable migration of VMs antar hosts without downtime. SAN fabric, FCoE, virtual HBA.

Bagian 06

Virtualization Security Concerns

Security challenges yang unique dan distinct dari conventional environments.

Virtualization telah mengubah konsep security di modern IT environments. Berbagai security challenges yang terkait dengan virtualization bersifat unique dan distinct dari conventional environments. Virtualization security concerns meliputi:

⚠
VM Escape

Attacker escapes dari VM ke hypervisor atau host OS. Dapat mengkompromi semua VM di host. Contoh: VENOM (2015), Cloudbleed. Paling berbahaya — blast radius = entire host.

⚠
VM-to-VM Attack

Attacker mengkompromi satu VM, lalu pivot ke VM lain di sama host. Bypass network security controls (VMs di same host tidak necessarily melalui firewall).

⚠
Snapshot Vulnerabilities

VM snapshots mengandung state lengkap VM termasuk password, keys, active sessions. Snapshot yang tidak terenkripsi = data breach. Old snapshots = security debt.

⚠
Migration Risks

Live migration (vMotion) memindahkan VM antar hosts — traffic bisa di-intercept jika network migration tidak encrypted. VM state di-expose saat transit.

⚠
Hypervisor Malware

Malware yang target hypervisor langsung — rootkit di hypervisor level. Sangat sulit dideteksi karena berjalan di bawah OS. Contoh: Blue Pill, Vitriol.

⚠
Resource Exhaustion

Satu VM yang consume semua resource (CPU, RAM, disk I/O) host = DoS untuk semua VM lain. Tidak ada network-level control yang dapat mencegah ini — perlu hypervisor-level limits.

Bagian 07

Virtualization Security Best Practices

Mitigasi security concerns via defense-in-depth di hypervisor, VM, dan network level.

🛡
Patch Hypervisor

Update hypervisor secara reguler dengan latest security patches. Hypervisor vulnerability = all VMs at risk. Enable auto-update atau scheduled maintenance window.

🔒
Isolate VMs

Gunakan VLAN dan virtual firewall untuk isolate VMs. VM sensitif (database) tidak boleh di same host dengan VM publik (web server) tanpa proper isolation.

📊
Resource Limits

Set CPU, RAM, dan I/O limits per VM. Prevent resource exhaustion DoS. Monitor resource usage — alert saat satu VM consume abnormal.

📸
Secure Snapshots

Encrypt snapshots. Delete old snapshots — jangan biarkan accumulate. Audit snapshot access. Treat snapshot seperti backup — secure storage.

🔐
Encrypt Migration

Enable encrypted vMotion/live migration. Jangan migrasi VM via unencrypted network. Use dedicated migration network (VLAN).

📋
VM Hardening

Hardened VM template: disable unnecessary services, install AV, enable firewall, minimal OS install. CIS Benchmarks untuk OS hardening per guest.

8.1 Benefits of Cloud Computing

💰
Cost Reduction

Reduce organization expenses — no upfront hardware cost, pay-per-use, no maintenance overhead. CapEx → OpEx transformation.

Distributed Workforce

Enable remote work — employees access apps & data from anywhere. Collaboration across geographies.

🔄
Disaster Recovery

Cloud provides built-in redundancy across availability zones. Backup & DR easier than on-premise.

Bagian 09

Cloud Service Models — IaaS, PaaS, SaaS

3 jenis layanan cloud berdasarkan level abstraction.

3 Cloud Service Models — Shared Responsibility Matrix
Gambar 5. Shared Responsibility Matrix — On-Premise (you manage all) → IaaS → PaaS → SaaS (provider manages most).
I
IaaS — Infrastructure as a Service

Provider supplies compute, storage, network infrastructure. You manage OS, apps, data. Examples: AWS EC2, Azure VM, Google Compute Engine. Most control, most responsibility.

P
PaaS — Platform as a Service

Provider supplies platform + runtime. You manage apps & data only. Examples: Heroku, Google App Engine, Azure App Service. Focus on development, not infrastructure.

S
SaaS — Software as a Service

Provider supplies complete application. You just use it. Examples: Gmail, Office 365, Salesforce, Dropbox. Least control, least responsibility.

Bagian 10

Cloud Deployment Models

4 model deployment: Public, Private, Hybrid, Community Cloud.

🌍
Public Cloud

Infrastructure dimiliki dan dioperasikan oleh cloud provider (AWS, Azure, GCP). Shared among multiple tenants. Kelebihan: low cost, no maintenance, unlimited scale. Kekurangan: less control, multi-tenant security concern, data residency.

🏢
Private Cloud

Infrastructure dimiliki dan dioperasikan oleh organisasi sendiri (on-premise atau hosted). Single tenant. Kelebihan: full control, maximum security, compliance. Kekurangan: high cost, maintenance burden, limited scalability.

🔄
Hybrid Cloud

Kombinasi public + private cloud. Sensitive data di private, scalable workload di public. Cloud bursting: run di private, burst ke public saat peak. Best of both worlds.

👥
Community Cloud

Infrastructure shared among several organizations dengan common concerns (compliance, mission). Contoh: government community cloud, healthcare community cloud. Collaborative approach.

Bagian 11

Cloud Security & Best Practices

Cloud environment poses threats & risks — mitigasi via shared responsibility & best practices.

Cloud environment juga menimbulkan banyak threats dan risks ke organisasi. Shared responsibility model adalah konsep kunci: cloud provider bertanggung jawab untuk security OF the cloud (infrastructure), customer bertanggung jawab untuk security IN the cloud (data, apps, access). Pemahaman batas tanggung jawab adalah kritikal.

11.1 Cloud Security Threats

⚠
Data Breach

Data breach di cloud bisa terjadi via misconfigured storage (S3 bucket public), weak access control, atau compromised credentials. Impact: lebih besar karena multi-tenant.

⚠
Account Hijacking

Cloud account credentials dicuri → attacker full control ke semua cloud resources. Phishing, credential stuffing, atau insider threat.

⚠
Insecure API

Cloud APIs yang insecure (weak auth, no rate limiting) dapat dieksploitasi untuk unauthorized access atau DoS.

⚠
Denial of Service

Attacker target cloud resources dengan massive traffic. Cloud auto-scale dapat memperburuk — resources scale up = cost increase = economic DoS.

11.2 Cloud Security Best Practices

🔐
Identity & Access Management

Implement strong IAM: MFA, role-based access, least privilege, rotate credentials, use IAM roles not access keys. SSO via SAML/OIDC. Regular access review.

🔒
Data Encryption

Encrypt data at rest (KMS, customer-managed keys) dan in transit (TLS 1.3). Tokenize sensitive data. Backup encryption.

🛡
Network Security

Security groups, network ACLs, VPC segmentation, private subnets, NAT gateway. WAF untuk web apps. DDoS protection (CloudFront, Cloudflare).

📊
Monitoring & Logging

Enable CloudTrail/Activity Log untuk audit. SIEM integration. Alert untuk suspicious activity (login from new geo, privilege escalation, mass data download).

📋
Compliance

Use compliance-ready cloud services (HIPAA, PCI DSS, FedRAMP, ISO 27001). Regular compliance assessment. Data residency control.

🔍
Configuration Management

Infrastructure as Code (Terraform, CloudFormation) untuk consistent config. CSPM (Cloud Security Posture Management) untuk detect misconfiguration. Baseline drift detection.

Cloud Security Tools: CSPM — Palo Alto Prisma Cloud, Wiz, Check Point CloudGuard; CWPP (Cloud Workload Protection) — CrowdStrike Falcon, Aqua Security, Sysdig; CASB — Netskope, Microsoft Defender for Cloud Apps, Zscaler; Cloud SIEM — Microsoft Sentinel, Splunk Cloud, Google Chronicle.

12.3 Workflow Praktikum 4 Sesi

Alur Praktikum — 4 Sesi, 20 Langkah, 1 Laporan Akhir
Gambar 6. Workflow 4 sesi praktikum Modul 06 — total 20 langkah hands-on.

12.4 Langkah Praktikum

Sesi 1 — VM Deployment dengan VirtualBox/KVM

1
Install VirtualBox & Create VMs

Install VirtualBox. Create 3 VMs: VM1 (Ubuntu Server — web server), VM2 (Ubuntu Server — database), VM3 (Kali Linux — attacker). Allocate: 2 vCPU, 2 GB RAM each. Set network: VM1 & VM2 di Internal Network, VM3 di NAT.

2
Configure Network & Isolation

Setup internal network antara VM1 & VM2. VM1 dapat reach VM2, tetapi VM3 (NAT) tidak dapat reach VM1/VM2 langsung. Test: ping antar VMs. Konfigurasi firewall (UFW) di VM1 & VM2 untuk restrict access.

3
Snapshots & Resource Limits

Take snapshot VM1 setelah install. Test: modify VM1 (install package), lalu restore snapshot — VM kembali ke state sebelum. Set resource limits: CPU cap 50%, RAM 1 GB. Test: run stress test di VM1, amati tidak exceed limit.

4
VM Security Hardening

Hardening: (a) disable root login SSH, (b) enable key-based auth only, (c) install UFW firewall, (d) enable automatic security updates, (e) install fail2ban. Test dari VM3 (attacker): brute force SSH → fail2ban block IP.

5
Laporan VM Lab

Buat laporan: (a) network diagram 3 VM, (b) isolation test results, (c) snapshot demo, (d) resource limit verification, (e) hardening checklist. Diskusikan: VM escape risk, migration security, snapshot security.

Sesi 2 — Docker Containerization

1
Install Docker

Install Docker di Ubuntu VM: curl -fsSL https://get.docker.com | sh. Verifikasi: docker --version, docker run hello-world. Add user ke docker group: usermod -aG docker $USER.

2
Build Custom Docker Image

Buat Dockerfile untuk web app sederhana (nginx + custom HTML). docker build -t mywebapp:v1 .. Run: docker run -d -p 8080:80 mywebapp:v1. Test: curl http://localhost:8080. Inspect: docker ps, docker exec -it <container> /bin/bash.

3
Docker Compose Multi-Container

Buat docker-compose.yml dengan 2 services: web (nginx) + db (postgres). Set network antar containers. docker-compose up -d. Test: web container dapat reach db container via service name. docker-compose down untuk cleanup.

4
Container Security

Security best practices: (a) run container as non-root user, (b) read-only filesystem --read-only, (c) drop capabilities --cap-drop ALL, (d) resource limits --memory=512m --cpus=0.5, (e) scan image dengan Trivy: trivy image mywebapp:v1.

5
Laporan Docker

Laporan: (a) Dockerfile + docker-compose.yml, (b) container run demo, (c) security hardening checklist, (d) Trivy scan results, (e) comparison VM vs Container (overhead, startup time, isolation). Diskusikan: container escape risk.

Sesi 3 — AWS IAM & S3 Setup

1
Create AWS Free Tier Account

Daftar di aws.amazon.com dengan Free Tier. Setup MFA di root account. Jangan gunakan root untuk daily tasks. Install AWS CLI: pip install awscli. Configure: aws configure dengan access key & secret key.

2
IAM Users, Groups & Roles

Buat IAM Group "Developers" dengan policy: AmazonEC2ReadOnlyAccess. Buat IAM User "dev-user" dan add ke group. Buat IAM Role "EC2-S3-Access" dengan S3 read policy. Test: login sebagai dev-user, coba create EC2 → denied (read-only). Attach role ke EC2 instance.

3
S3 Bucket dengan Access Control

Buat S3 bucket "my-secure-bucket-lab". Set: (a) Block ALL public access, (b) Enable default encryption (SSE-S3), (c) Versioning enabled, (d) Bucket policy: allow only dari specific VPC. Upload test file. Test: public access → denied. Access via IAM role → allowed.

4
VPC & Security Groups

Buat custom VPC: public subnet (web) + private subnet (db). Security group web: allow 80, 443 dari Internet. Security group db: allow 3306 hanya dari web security group. Launch EC2 di masing-masing subnet. Test: Internet → web = OK, Internet → db = blocked, web → db = OK.

5
Laporan Cloud IAM

Laporan: (a) IAM structure (users, groups, roles, policies), (b) S3 bucket configuration, (c) VPC network diagram, (d) security group rules, (e) shared responsibility analysis — apa yang Anda manage vs AWS manage. Diskusikan: least privilege, MFA, data residency.

Sesi 4 — Cloud Security Audit

1
Install Prowler

Prowler adalah open-source AWS security assessment tool. Install: pip install prowler atau clone dari GitHub. Configure AWS credentials. Run basic scan: prowler aws. Tunggu 5-10 menit untuk assessment lengkap.

2
Analyze Prowler Results

Review findings: (a) Critical — root MFA not enabled, (b) High — IAM access keys older than 90 days, (c) Medium — S3 bucket without encryption, (d) Low — password policy too weak. Catat setiap finding dengan severity & recommendation.

3
Remediate Findings

Fix critical findings: (a) Enable MFA untuk semua IAM users, (b) Rotate old access keys, (c) Enable S3 encryption untuk all buckets, (d) Strengthen IAM password policy (min 14 char, require symbols), (e) Delete unused security groups. Re-run Prowler untuk verify.

4
Scout Suite Multi-Cloud Audit

Install Scout Suite: pip install scoutsuite. Run: scout aws --report-dir ./report. Compare dengan Prowler — Scout Suite berikan dashboard yang lebih visual. Identifikasi findings yang miss oleh Prowler (atau sebaliknya).

5
Cloud Security Laporan

Laporan: (a) Prowler + Scout Suite findings, (b) remediation actions taken, (c) before/after comparison, (d) cloud security posture score, (e) recommendations untuk continuous improvement. Diskusikan: CSPM, CWPP, CASB — mana yang paling relevant untuk organisasi?

12.6 Checklist Evaluasi
