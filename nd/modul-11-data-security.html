Bagian 02

Data Security & Its Importance

Mengapa data security penting — data loss risks di business environment.

Data security adalah practice of protecting digital information throughout its lifecycle — dari creation, storage, transmission, hingga destruction. Data security melibatkan combination dari policies, procedures, dan technical controls yang bekerja sama untuk melindungi data dari unauthorized access, corruption, atau theft.

💰
Financial Loss

Data breach rata-rata costs $4.45 million (IBM 2023). Termasuk: remediation, legal fees, regulatory fines, lost business, reputation damage.

⚖
Regulatory Compliance

GDPR fines up to €20M, PCI DSS fines $5K-$100K/month, HIPAA $50K per violation. Data security = compliance requirement.

🤝
Trust & Reputation

Data breach → customer trust loss → customer churn → revenue decline. Reputational damage dapat bertahun-tahun untuk recover.

⚡
Operational Disruption

Ransomware dapat halt business operations for weeks. Data loss = downtime = lost productivity + lost revenue.

Bagian 04

Data Security Technologies

4 teknologi inti: Tokenization, Data Masking, Data Destruction, Data Retention.

🔄
Tokenization

Mengganti sensitive data dengan non-sensitive token. Token tidak memiliki meaning jika dicuri. Original data disimpan di secure token vault. Contoh: credit card number → token untuk e-commerce. PCI DSS compliant karena token bukan cardholder data.

🎭
Data Masking

Mengganti atau obscure sensitive data dengan characters lain. Contoh: 1234-5678-9012-3456 → XXXX-XXXX-XXXX-3456. Digunakan di: UI display, test databases, log files. Tidak mengenkripsi — hanya menyembunyikan dari view.

💥
Data Destruction

Permanent removal of data dari storage media. Methods: physical destruction (shredding, crushing), degaussing (magnetic erase), cryptographic erase (destroy encryption key), overwriting (write zeros/random). Penting saat dispose device.

📅
Data Retention

Process of storing dan maintaining important information untuk meeting business/legal requirements. Retention policy menentukan: what data to keep, how long, where, how to dispose. Compliance: HIPAA 6 years, SOX 7 years, GDPR "no longer than necessary".

Bagian 05

Security Controls for Data Encryption

3 level encryption: disk, file, dan removable-media.

💾
Disk Encryption

Encrypt entire disk — full disk encryption (FDE). Semua data di disk terenkripsi, including OS. Tools: BitLocker (Windows), LUKS (Linux), FileVault (macOS), VeraCrypt (cross-platform). Protect jika device dicuri.

📄
File Encryption

Encrypt individual files atau folders. Granular control — hanya file sensitif yang terenkripsi. Tools: EFS (Encrypting File System Windows), GPG, 7-Zip (AES-256), VeraCrypt containers. File-level key management.

🔌
Removable-media Encryption

Encrypt USB drives, external HDDs, SD cards. Tools: BitLocker To Go, VeraCrypt, SanDisk SecureAccess. Critical: USB mudah hilang/dicuri — encryption prevents data exposure.

🗄
Database Encryption

Transparent Data Encryption (TDE) — encrypt database files at rest. Application transparent — no code change needed. Column-level encryption untuk specific sensitive columns. Examples: SQL Server TDE, Oracle TDE, MongoDB encryption.

Bagian 06

Data Backup & Retention

Strategi backup untuk ensure data availability saat loss/corruption/disaster.

Data backup adalah process of creating copies of data yang dapat digunakan untuk restore setelah data loss event. Data loss dapat terjadi karena: hardware failure, accidental deletion, malware/ransomware, natural disaster, atau theft. Backup adalah last line of defense untuk data availability.

6.1 Reasons for Data Loss

⚠
Hardware Failure

Hard drive crash, SSD wear-out, server failure. Most common cause of data loss.

⚠
Human Error

Accidental deletion, overwrite, formatting wrong drive. Second most common.

⚠
Malware/Ransomware

Ransomware encrypts data dan demands payment. Rising threat — backup = best defense.

⚠
Natural Disaster

Flood, fire, earthquake destroys data center. Offsite backup = essential.

6.2 Benefits of Data Backup

🔄
Business Continuity

Restore operations quickly setelah data loss event. Minimize downtime = minimize revenue loss.

🛡
Ransomware Protection

If data backed up, tidak perlu pay ransom. Best defense against ransomware.

📋
Compliance

Banyak regulasi require backup: HIPAA, SOX, PCI DSS. Backup = compliance evidence.

🧘
Peace of Mind

Knowing data can be restored = less stress untuk IT dan management.

Bagian 07

Backup Types & Strategy

Full, Incremental, Differential + Onsite, Offsite, Cloud backup.

3 Backup Types + 3 Backup Locations
Gambar 3. 3 backup types (Full, Incremental, Differential) + 3 backup locations (Onsite, Offsite, Cloud). Best practice: 3-2-1 rule.
3-2-1 Backup Rule (Golden Rule): Simpan 3 copies data, di 2 different media, dengan 1 copy offsite. Contoh: production data + onsite backup (NAS) + cloud backup. Ini adalah best practice yang recommended oleh semua security professionals dan compliance frameworks.

7.1 Data Retention Policy

Data retention adalah process of storing dan maintaining important information untuk meeting business atau legal requirements. Data retention policy menentukan: what data to keep, how long to keep, where to store, how to dispose when retention period expires.

📋
Steps for Retention Policy

(1) Identify data types & regulatory requirements. (2) Classify data by sensitivity. (3) Define retention period per data type. (4) Define storage location & format. (5) Define disposal method. (6) Document & communicate policy.

✓
Best Practices

• Automate retention enforcement (don't rely on manual). • Review policy annually. • Align dengan compliance requirements. • Document legal hold process. • Secure disposal (not just delete). • Audit retention compliance periodically.

Bagian 08

Data Loss Prevention (DLP)

Software products & processes yang prevent unauthorized data transfer.

Data Loss Prevention (DLP) mencakup set of software products dan processes yang tidak mengizinkan sensitive information meninggalkan organisasi. DLP membantu security professionals dalam mengontrol what data end users can transfer. DLP rules block the transfer of sensitive data dan alert security team. DLP software diimplementasikan sesuai dengan organizational rules yang ditetapkan oleh management.

🛡
What DLP Does

DLP monitors, detects, dan blocks sensitive data movements: email, USB, cloud upload, print, screenshot, clipboard copy. DLP ensures sensitive information tidak meninggalkan organisasi — baik intentionally (insider threat) maupun unintentionally (accidental leak).

🎯
DLP Used For

• Prevent data breaches — block sensitive data exfiltration
• Compliance — GDPR, HIPAA, PCI DSS require data protection
• IP protection — prevent trade secret theft
• Insider threat — detect & block malicious employees
• BYOD security — monitor data on personal devices

Bagian 10

DLP Solutions & Best Practices

Tools dan best practices untuk successful DLP implementation.

🪟
Windows Information Protection (WIP)

Microsoft endpoint DLP capability. Helpful untuk organizations yang allow personal devices. Integrates dengan Windows Defender ATP untuk data discovery dan endpoint protection.

🆓
MyDLP

Free dan open-source DLP solution. Allows organizations to secure sensitive data across: network, endpoint, storage, messaging, printers, removable storage, screenshots.

🛡
Symantec DLP

Enterprise-grade DLP. Comprehensive: network, endpoint, storage, cloud. Advanced content analysis, machine learning-based detection. Market leader.

🔒
Other Solutions

SecureTrust DLP, Check Point DLP, Digital Guardian Endpoint DLP, Forcepoint DLP, Microsoft Purview (formerly Microsoft 365 DLP).

10.1 DLP Implementation Best Practices

1
Identify Objectives

Identify main objective of DLP — compliance? IP protection? Insider threat? Different objectives = different configuration.

2
Evaluate Vendors

Evaluate available DLP vendors. Ensure product compatible dengan existing infrastructure dan supports required data types.

3
Start Minimal

Implement DLP dengan minimal base untuk reduce false positives. Monitor-only mode first, lalu switch to enforcement mode setelah tuning.

4
Enhance Policies

Enhance DLP policies untuk support effective operations dan eliminate false positives. Continuous tuning based on real incidents.

DLP Implementation Phased Approach: (1) Discover — scan dan classify all data (where is sensitive data?). (2) Monitor — monitor data movement tanpa blocking (learn patterns). (3) Protect — enforce policies (block + alert). (4) Maintain — continuous tuning, review, dan improvement. Jangan langsung block di hari pertama — too many false positives = user frustration.

11.4 Langkah Praktikum

Sesi 1 — Disk Encryption (LUKS + BitLocker)

1
LUKS Disk Encryption di Ubuntu

Install: apt install cryptsetup. Tambah virtual disk ke VM. Format dengan LUKS: cryptsetup luksFormat /dev/sdb. Open: cryptsetup luksOpen /dev/sdb secure_data. Format filesystem: mkfs.ext4 /dev/mapper/secure_data. Mount: mount /dev/mapper/secure_data /mnt/secure.

2
Test LUKS Encryption

Write test file: echo "Secret data" > /mnt/secure/secret.txt. Unmount: umount /mnt/secure. Close: cryptsetup luksClose secure_data. Try mount without key: mount /dev/sdb /mnt/test → harus fail (encrypted). Re-open dengan key → data accessible.

3
BitLocker di Windows

Di Windows VM: Control Panel → BitLocker Drive Encryption → Turn on BitLocker. Pilih: save recovery key (to file, Microsoft account, atau print). Pilih encryption: used disk space only (faster) atau entire drive. Run BitLocker system check. Reboot → disk encrypted.

4
VeraCrypt File Container

Download VeraCrypt. Create volume → Create file container → Standard volume. Pilih location, size (100MB), password (strong). Format dengan AES + SHA-512. Mount container → copy sensitive files. Unmount → data encrypted. Test: buka container tanpa password → fail.

5
Laporan Disk Encryption

Laporan: (a) LUKS setup + test, (b) BitLocker setup, (c) VeraCrypt container demo, (d) comparison: LUKS vs BitLocker vs VeraCrypt, (e) security analysis. Diskusikan: apa yang terjadi jika password lupa? Recovery key importance.

Sesi 2 — Data Backup & Recovery

1
Setup Backup dengan Rsync

Create test data: mkdir -p /data/{docs,photos,videos} && for d in docs photos videos; do for i in $(seq 1 10); do echo "File $i" > /data/$d/file$i.txt; done; done. Setup rsync backup: rsync -avz --backup --backup-dir=/backup/$(date +%Y%m%d) /data/ /backup/current/. Verify: ls /backup/current/.

2
3-2-1 Backup Implementation

3 copies: (1) original /data, (2) onsite backup /backup, (3) compressed archive. 2 media: disk (/backup) + USB drive. 1 offsite: tar + encrypt + upload to cloud (AWS S3 atau similar). Script: tar -czf - /data | openssl enc -aes-256-cbc -salt -out backup_$(date).tar.gz.enc -pbkdf2.

3
Test Restore

Simulate data loss: rm -rf /data/*. Restore dari backup: rsync -avz /backup/current/ /data/. Verify: ls /data/ — all files restored. Test restore dari encrypted archive: openssl enc -d -aes-256-cbc -in backup.tar.gz.enc -out backup.tar.gz -pbkdf2 && tar -xzf backup.tar.gz.

4
Ransomware Recovery Simulation

Simulate ransomware: for f in /data/*/*; do echo "ENCRYPTED" > $f; done (corrupt all files). Without backup: data lost permanently. With backup: rm -rf /data/* && rsync -avz /backup/current/ /data/ — fully recovered. Pelajari: backup = best defense against ransomware.

5
Automated Backup + Laporan

Setup cron job untuk daily backup: crontab -e → 0 2 * * * /usr/bin/rsync -avz /data/ /backup/current/. Setup log rotation. Laporan: (a) backup strategy diagram, (b) 3-2-1 implementation, (c) restore test results, (d) ransomware recovery demo, (e) automated backup config.

Sesi 3 — DLP Implementation dengan MyDLP

1
Install MyDLP

Download MyDLP dari mydlp.com. Install di Ubuntu Server: dpkg -i mydlp-package.deb. Configure: set admin password, network interface untuk monitoring. Access web console: https://localhost:8443.

2
Configure DLP Rules

Buat DLP rules: (a) Credit card number detection — regex pattern untuk 16-digit numbers, (b) SSN detection — pattern untuk social security numbers, (c) Keyword detection — "confidential", "proprietary", "internal only", (d) File type blocking — block .xlsx, .pdf transfer via email/USB.

3
Test DLP — Monitor Mode

Set DLP ke monitor-only mode (log, don't block). Test: (a) email dengan fake credit card number, (b) copy file containing "confidential" ke USB, (c) upload .xlsx ke cloud storage. Check DLP dashboard — semua incidents harus terdeteksi dan ter-log.

4
Switch to Enforcement Mode

Set DLP ke enforcement mode (block + alert). Re-test: (a) email dengan credit card → blocked, (b) copy "confidential" file ke USB → blocked, (c) upload .xlsx → blocked. Verify: legitimate non-sensitive traffic masih works (false positive check).

5
Tuning & Laporan

Review false positives → tune rules. Laporan: (a) DLP architecture, (b) rules configured, (c) monitor mode results, (d) enforcement mode results, (e) false positive analysis, (f) recommendations. Diskusikan: phased approach (discover → monitor → protect → maintain).

Sesi 4 — Data Masking, Tokenization & Destruction

1
Data Masking di PostgreSQL

Install PostgreSQL. Buat table customers dengan: name, email, credit_card, SSN. Implement masking via view: CREATE VIEW customers_masked AS SELECT name, LEFT(email,2)||'***' AS email, 'XXXX-XXXX-XXXX-'||RIGHT(credit_card,4) AS credit_card, 'XXX-XX-'||RIGHT(ssn,4) AS ssn FROM customers;. Test: original vs masked view.

2
Tokenization Implementation

Buat tokenization table: tokenization(token_id SERIAL, original_hash TEXT, token TEXT). Python script: hash original credit card → generate random token → store mapping. Replace credit card dengan token di application database. Original data only di secure token vault.

3
Secure Data Destruction

Demonstrasi 4 destruction methods: (1) shred: shred -v -n 3 -z secret.txt (3 passes + zero). (2) dd overwrite: dd if=/dev/urandom of=/dev/sdb bs=1M (whole device). (3) cryptographic erase: destroy LUKS key → data unrecoverable. (4) physical destruction: discuss shredding, crushing (no demo — just explain).

4
Verify Destruction

After shred: hexdump secret.txt → random data (no original content). After dd: fdisk -l /dev/sdb → no partitions. After crypto erase: try cryptsetup luksOpen → fail (key destroyed). Verify: data permanently unrecoverable.

5
Laporan Masking & Destruction

Laporan: (a) data masking SQL + before/after, (b) tokenization architecture + code, (c) destruction methods demo + verification, (d) comparison: masking vs tokenization vs encryption, (e) use case per technology. Diskusikan: kapan masking, kapan tokenization, kapan encryption.

Bagian 12

Ringkasan Modul

Rangkuman poin-poin kritis yang telah dibahas dalam Modul 11 Data Security.

📋 Yang Telah Dipelajari

  • Data security importance — data breach costs $4.45M average, regulatory fines, trust loss, operational disruption.
  • 3 states of data — At Rest (stored, disk encryption), In Use (processed, endpoint DLP), In Transit (moving, TLS/VPN). Each state needs different controls.
  • 4 data security technologies — Tokenization (replace with token), Data Masking (obscure sensitive data), Data Destruction (permanent removal: shred, degauss, crypto-erase, overwrite), Data Retention (store & maintain per policy).
  • Encryption controls — Disk encryption (BitLocker, LUKS, FileVault), File encryption (EFS, GPG, VeraCrypt), Removable-media encryption (BitLocker To Go, VeraCrypt), Database encryption (TDE).
  • Data backup — Reasons for data loss: hardware failure, human error, malware/ransomware, natural disaster. Benefits: business continuity, ransomware protection, compliance, peace of mind.
  • 3 backup types — Full (all data, slow backup/fast restore), Incremental (changed since last backup, fast backup/slow restore), Differential (changed since last full, balanced).
  • 3 backup locations — Onsite (fast, vulnerable to site disaster), Offsite (protected, slower), Cloud (scalable, automated, internet dependent). 3-2-1 rule: 3 copies, 2 media, 1 offsite.
  • Data retention — policy determines what to keep, how long, where, how to dispose. Steps: identify data types, classify, define retention period, define storage, define disposal, document.
  • Data Loss Prevention (DLP) — software products & processes that prevent sensitive data from leaving organization. Monitors, detects, blocks data movement.
  • 3 DLP types — Endpoint DLP (data in use, monitors USB/print/clipboard), Network DLP (data in transit, monitors email/web/FTP), Storage DLP (data at rest, scans file servers/databases/cloud).
  • DLP solutions — Windows Information Protection (WIP), MyDLP (open-source), Symantec DLP, SecureTrust DLP, Check Point DLP, Digital Guardian, Microsoft Purview.
  • DLP best practices — identify objectives, evaluate vendors, start minimal (reduce false positives), enhance policies. Phased: discover → monitor → protect → maintain.
  • Praktikum 4 sesi — Disk encryption (LUKS/BitLocker/VeraCrypt), Backup & recovery (3-2-1 rule + ransomware sim), DLP deployment (MyDLP), Masking & tokenization + destruction.
Key Takeaway: Data security adalah multi-layered approach — protect data di semua 3 states (rest, use, transit) dengan combination dari encryption, DLP, backup, masking, dan tokenization. Backup adalah last line of defense terhadap ransomware dan data loss. DLP prevents data from leaving organization. 3-2-1 backup rule adalah golden standard. Encryption everywhere — at rest, in transit, in backup. Modul ini melengkapi Modul 10 (Cryptography) dengan practical application dari crypto untuk protect data.
