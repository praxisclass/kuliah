Tujuan Pembelajaran

Mengapa keamanan IoT menjadi tantangan kritis dengan attack surface yang jauh lebih luas dari mobile device.

Penggunaan perangkat Internet of Things (IoT) dalam infrastruktur IT enterprise telah menciptakan perimeter keamanan yang sangat luas. Perangkat IoT menggunakan jaringan dan cloud secara bersamaan, tetapi sangat rentan terhadap serangan malware, ransomware, dan botnet. Bagian 02

Definisi & Komponen IoT

Internet of Things sebagai jaringan perangkat ber-IP dengan kemampuan sensing, collecting, dan sending data melalui sensor, komunikasi hardware, dan prosesor embedded.

2.1 Apa itu IoT?

Internet of Things (IoT), juga dikenal sebagai Internet of Everything (IoE), adalah jaringan perangkat komputasi yang web-enabled dan memiliki kemampuan untuk sensing (merasakan), collecting (mengumpulkan), dan sending (mengirim) data menggunakan sensor, hardware komunikasi, dan prosesor yang tertanam di dalam perangkat. Dalam IoT, istilah "thing" merujuk pada perangkat yang ditanamkan pada objek alami, buatan manusia, atau buatan mesin dan memiliki fungsionalitas untuk berkomunikasi melalui jaringan.

IoT memanfaatkan teknologi yang sudah ada maupun yang sedang berkembang — sensing, networking, dan robotics — sehingga memungkinkan pengguna mencapai analisis yang lebih dalam, otomatisasi, dan integrasi dalam sebuah sistem. Dengan meningkatnya kemampuan jaringan mesin dan peralatan sehari-hari di berbagai sektor (perkantoran, rumah, industri, transportasi, bangunan, dan wearable devices), IoT membuka peluang baru untuk peningkatan bisnis dan kepuasan pelanggan.

Fitur Kunci IoT

🔗
Connectivity

Konektivitas antar perangkat melalui berbagai protokol — Wi-Fi, Bluetooth, Zigbee, Z-Wave, LoRa, 5G, NB-IoT. Setiap "thing" mendapat IP address (IPv4/IPv6) untuk komunikasi global.

📡
Sensors

Sensor embedded mengumpulkan data lingkungan: suhu, kelembaban, tekanan, lokasi (GPS), getaran, cahaya, gas, elektrokimia, RFID. Sensor adalah mata dan telinga IoT.

🧠
Artificial Intelligence

IoT modern dipadukan dengan AI/ML untuk analisis prediktif, anomaly detection, dan autonomous decision-making. Tanpa AI, IoT hanyalah kumpulan data mentah.

📏
Small Devices

Perangkat IoT umumnya kecil, low-power, dengan microcontroller (MCU) terbatas. Keterbatasan resource ini menjadi tantangan utama implementasi keamanan.

⚡
Active Engagement

IoT tidak sekadar pasif mengumpulkan data — perangkat aktif terlibat dalam interaksi dua arah dengan pengguna dan sistem lain melalui aktuator dan control loop.

🌐
Edge Computing

Pemrosesan data di tepi jaringan (edge) sebelum dikirim ke cloud — mengurangi latensi, menghemat bandwidth, dan meningkatkan privasi data sensitif.

2.2 Tiga Dimensi Konektivitas IoT

Mengapa Organisasi Memilih IoT — 3D Plane of Connectivity
Gambar 3. Tiga dimensi IoT — Place × Thing × Time memungkinkan konektivitas tanpa batas untuk anyone, anything, anytime, anywhere.

Perangkat IoT bekerja pada bidang tiga dimensi yang menawarkan konektivitas untuk siapa saja kapan saja, untuk hal apa pun, dan dari mana pun. IoT memfasilitasi koneksi ke berbagai objek — interaksi Human-to-Thing (H2T) menggunakan peralatan generik, Thing-to-Thing (T2T) antar PC/perangkat, dan Human-to-Human (H2H) tanpa menggunakan PC. Pengguna dapat menghubungkan ke perangkat IoT di mana pun baik saat dalam perjalanan, di dalam ruangan (jauh dari PC), di luar ruangan, atau di PC.

2.3 Komponen Utama Teknologi IoT

📡
Sensing Technology

Sensor yang tertanam dalam perangkat memperoleh berbagai informasi dari lingkungan sekitar: suhu, gas, lokasi, kondisi kerja mesin industri, dan data kesehatan pasien. Sensor adalah sumber data utama IoT.

🌐
IoT Gateways

Gateway menjembatani kesenjangan antara perangkat IoT (jaringan internal) dan pengguna akhir (jaringan eksternal). Data dari sensor dikumpulkan dan dikirim ke pengguna atau cloud melalui gateway.

☁
Cloud Server / Data Storage

Setelah melewati gateway, data tiba di cloud untuk disimpan dan dianalisis. Data yang sudah diproses kemudian dikirim ke pengguna, yang akan mengambil tindakan berdasarkan informasi yang diterima.

📱
Remote Control via Mobile Apps

Pengguna akhir menggunakan perangkat remote (ponsel, tablet, laptop) dengan aplikasi mobile untuk memantau, mengontrol, mengambil data, dan mengambil tindakan pada perangkat IoT dari lokasi jauh.

2.4 Contoh Workflow: Sistem Keamanan Pintar

Workflow Sistem Keamanan IoT — Sensor → Gateway → Cloud → Mobile
Gambar 4. Workflow 5 tahap IoT untuk smart security system — sensor → gateway → cloud → user → command balik ke aktuator.

Contoh konkret: sistem keamanan pintar terintegrasi dengan gateway yang menghubungkan perangkat ke internet dan infrastruktur cloud. Data storage di cloud mencatat informasi setiap perangkat (device ID, status, siapa yang mengakses, frekuensi akses, durasi akses terakhir). Koneksi ke cloud server melalui web services. Pengguna dengan aplikasi mobile mengautentikasi diri — jika kredensial cocok dengan yang tersimpan di cloud, akses diberikan; jika tidak, akses ditolak. Saat sistem keamanan mendeteksi aktivitas tidak wajar, alert dikirim ke cloud melalui gateway, lalu cloud mencocokkan device ID dengan user terkait, dan akhirnya pengguna akhir menerima alert.

Insight Keamanan: Workflow IoT di atas menunjukkan titik-titik kritis di mana penyerang dapat mengintervensi: (1) sensor dapat di-spoof, (2) gateway dapat di-compromise untuk manipulasi data, (3) cloud dapat bocor data, (4) mobile app dapat di-phishing. Setiap hop adalah trust boundary yang memerlukan autentikasi & enkripsi.

3.3 Studi Kasus per Sektor

🏠
Smart Home

Perangkat pintar terhubung internet yang melayani pengguna akhir: thermostat, lighting systems, security systems di bangunan residensial. Contoh: Nest Thermostat yang belajar pola suhu penghuni dan menghemat energi 10-15%.

❤
Healthcare & Life Science

Wearable devices, health monitoring devices seperti implanted heart pacemakers, ECG/EKG, surgical equipment, telemedicine. Implant modern dapat mengirim data jantung langsung ke kardiolog secara real-time.

🏭
Industrial IoT (IIoT)

Tumbuh melalui 3 pendekatan: meningkatkan produksi untuk revenue, teknologi intelligent yang mengubah cara produksi, dan model bisnis hibrida baru. Contoh: predictive maintenance sensor mesin yang mencegah downtime.

🚗
Transportation

Konsep Vehicle-to-Vehicle (V2V), Vehicle-to-Roadside (V2R), dan Vehicle-to-Pedestrian (V2P) communication. Meningkatkan kondisi lalu lintas, sistem navigasi, dan skema parkir.

🛒
Retail

IoT digunakan untuk payments, advertisements, dan tracking/monitoring produk untuk mencegah pencurian dan kerugian, meningkatkan revenue. Contoh: smart shelves yang auto-order stok.

💻
IT and Networks

IoT di lingkungan IT mencakup mesin kantor seperti printers, fax, copiers, serta PBX monitoring systems. Memudahkan komunikasi antar endpoint dan pengiriman data jarak jauh.

Insight Penting: Setiap sektor memiliki profil risiko unik. Healthcare IoT (implant) menuntut life-critical availability. Industrial IoT menuntut deterministic latency. Smart Home menuntut privacy by design. Strategi keamanan IoT harus disesuaikan per use case.
Bagian 04

Arsitektur IoT

Empat lapisan arsitektur IoT — Device, Communication, Cloud, dan Process — dirancang untuk memenuhi kebutuhan berbagai sektor.

Arsitektur IoT mencakup beberapa lapisan yang saling terhubung untuk mengumpulkan, menyimpan, dan memproses data. Lapisan-lapisan ini dirancang sedemikian rupa sehingga dapat memenuhi kebutuhan berbagai sektor: masyarakat, industri, enterprise, dan pemerintah. Arsitektur umum IoT ecosystem berbeda untuk setiap organisasi, tetapi model referensi yang banyak digunakan mencakup 4 lapisan utama berikut.

4.1 4 Lapisan Arsitektur IoT

4-Layer IoT Architecture — Device → Communication → Cloud → Process
Gambar 6. Arsitektur 4-layer IoT — Device mengumpulkan data, Communication mengirim, Cloud menyimpan/proses, Process mengubah menjadi keputusan bisnis.

4.2 Komponen Building Block Arsitektur IoT

Gateways (Field Gateways)
Perangkat yang mentransmisikan data dari things ke cloud dan sebaliknya. Fungsi: pre-processing & filtering data sebelum transmit ke cloud (mengurangi volume), mengirimkan control commands dari cloud ke things untuk dieksekusi aktuator.
Cloud Gateways
Fitur: data compression, mengamankan transfer data antara field gateways dan cloud IoT servers, memastikan kompatibilitas protokol berbeda, dan berkomunikasi dengan field gateways melalui protokol yang didukung gateway.
Streaming Data Processors
Memastikan tidak ada data yang hilang atau corrupt. Fitur: transisi data efektif ke data lake, application control. Processor ini adalah jantung aliran data real-time IoT.
Data Lakes
Menyimpan data dari perangkat terhubung dalam format natural. Jika data dibutuhkan untuk insight bermakna, diekstrak dari data lake dan dimuat ke big data warehouse.
Big Data Warehouses
Hanya berisi data yang sudah dibersihkan, terstruktur, dan di-match. Menyimpan: context information tentang things/devices (lokasi sensor), commands yang dikirim control applications ke things.
Data Analytics
Membantu data analysts menemukan trends dan actionable insights. Analisis dalam bentuk schema, diagram, dan infographics mengungkap: device performance, inefficiencies IoT system dan cara enhancement. Korelasi manual membantu membuat algoritma untuk control applications.
Machine Learning
Memungkinkan data analysts membuat models untuk control applications. Model diupdate reguler sesuai data di big data warehouse. Contoh: model pengenalan pola perilaku karyawan (jam masuk/keluar) untuk auto-adjust lampu ruangan.
Control Applications
Mengirim automatic commands & alerts ke aktuator. Contoh: saat pre-failure situation terdeteksi, sensor memantau state device, IoT system mengirim notifikasi otomatis ke system engineer. Dua tipe: rule-based (rule dari specialist) dan ML-based (model yang diupdate reguler).
User Applications
Aplikasi web/mobile untuk mengubah behavior application controls. Memungkinkan user: connect ke IoT system, monitor & control smart things (kirim command ke control apps, set option automatic behavior) saat terhubung ke network of similar things.
Best Practice: Arsitektur IoT yang baik harus mendukung horizontal scaling (jumlah device bertambah) dan vertical scaling (berbagai IoT solution). Cloud tier harus bisa orchestrate seluruh workflow IoT end-to-end.
Bagian 05

Model Komunikasi IoT

Empat model komunikasi IoT yang menyoroti fleksibilitas perangkat IoT dalam berkomunikasi satu sama lain atau dengan client.

Teknologi IoT menggunakan berbagai model komunikasi teknis, masing-masing dengan karakteristik unik. Model-model ini menyoroti fleksibilitas perangkat IoT dalam berkomunikasi satu sama lain atau dengan client. Pemilihan model komunikasi yang tepat sangat mempengaruhi arsitektur keamanan, latensi, dan skalabilitas solusi IoT.

5.1 Empat Model Komunikasi — Visualisasi

4 IoT Communication Models — Perbandingan Arsitektur
Gambar 7. Perbandingan 4 model komunikasi IoT — D2D (langsung), D2C (ke cloud), D2G (via gateway), C2C (antar cloud).

5.2 Penjelasan Detail Setiap Model

D2D
Device-to-Device Communication

Perangkat saling berinteraksi langsung melalui internet tetapi didominasi protokol ZigBee, Z-Wave, atau Bluetooth. Paling umum di smart home: thermostat, light bulb, door lock, CCTV, fridge — transfer paket data kecil dengan data rate rendah.

Populer juga di komunikasi wearable devices. Contoh: ECG/EKG yang dikenakan pasien di-pair ke smartphone, mengirim notifikasi darurat.

Low latency No cloud needed Limited range
D2C
Device-to-Cloud Communication

Perangkat berkomunikasi dengan cloud langsung, bukan dengan client. Menggunakan Wi-Fi, Ethernet, atau Cellular. Contoh: CCTV yang diakses via smartphone dari lokasi remote.

Device tidak dapat berkomunikasi langsung dengan client — harus lewat cloud. Client input kredensial → akses cloud → akses device.

Global access Cloud-dependent Latency variabel
D2G
Device-to-Gateway Communication

Perangkat IoT berkomunikasi dengan gateway intermediate, yang kemudian berkomunikasi dengan cloud service. Gateway bisa smartphone atau hub yang menyediakan security features dan protocol/data translation.

Protokol umum: ZigBee dan Z-Wave. Jika gateway adalah smartphone, bisa berupa aplikasi yang berinteraksi dengan IoT device dan cloud. Contoh: smart TV yang connect ke cloud via mobile app.

Protocol translation Edge security Extra hop
C2C
Cloud-to-Cloud (Back-End Sharing)

Memperluas D2C sehingga data IoT dapat diakses oleh pihak ketiga yang berwenang. Perangkat upload data ke cloud, lalu diakses/dianalisis oleh pihak ketiga.

Contoh: analyzer konsumsi energi tahunan/bulanan perusahaan. Hasil analisis digunakan untuk mengurangi pengeluaran energi via teknik energy-harvesting atau saving.

3rd-party sharing OAuth 2.0 Privacy concern
Trade-off Penting: Pemilihan model komunikasi menentukan postur keamanan: D2D rentan di physical layer (jamming, eavesdropping); D2C rentan di cloud (data breach); D2G menambah attack surface gateway; C2C memperumit consent & data sovereignty. Tidak ada model "paling aman" — yang ada adalah model "paling sesuai use case".
Bagian 06

Lingkungan IoT-Enabled

Tiga tier lingkungan IoT enterprise: Things/Devices, Gateway/Control, dan Cloud/Platform — dengan 5 fitur kunci.

Lingkungan IT IoT-enabled yang khas terdiri dari perangkat/things yang menggunakan gateway untuk berkomunikasi melalui jaringan ke server back-end organisasi yang menjalankan IoT cloud platform. Platform IoT ini memungkinkan integrasi informasi IoT ke dalam organisasi.

6.1 Tiga Tier Lingkungan IoT-Enabled

3-Tier IoT-Enabled IT Environment
Gambar 8. 3-tier IoT-enabled environment — Things (devices) → Gateway (pre-process) → Cloud (compute/insights).

6.2 Fungsi Setiap Tier

T1
Things/Devices Tier

Smartphone, wearable, autonomous machines, tag (RFID/NFC/QR) yang mengumpulkan data via sensor. Mentransfer telemetry/command ke gateway via protokol wired/wireless. Dapat mengontrol state device lain — switch off faulty device atau raise alarm.

T2
Gateway/Control Tier

Fokus pada komunikasi, offload processing, dan driving actions. Pre-process huge data dari sensor sebelum kirim ke cloud — mengurangi unwanted data. Bertindak sebagai proxy/edge device untuk legacy & low-power devices yang tidak bisa langsung register ke IoT platform.

T3
Cloud IoT Platform Tier

Fokus pada data computation untuk insights dan business value. Bertindak sebagai middleware yang orchestrate seluruh IoT workflow. Backend business analytics untuk run event processes, create/adapt business rules berdasarkan historical trends.

6.3 Lima Fitur Kunci IoT-Enabled IT Environment

📡
Real-time Monitoring

Memantau IoT assets, processing products, memelihara flow, membantu detect issue, dan mengambil tindakan segera. Dasar dari operasional IoT yang responsif.

📊
Real-time Analytics

Menganalisis IoT things dan mengambil langkah sesuai. Menyediakan grafik dan real-time streaming analytics, memungkinkan bisnis overview performance dan produksi.

🛡
Multi-layer Security

Mencegah akses tidak sah ke IoT things menggunakan MFA, TLS, device identity management, dll. Pendekatan berlapis untuk defense-in-depth.

📥
Data Collection

Pertukaran data antar organisasi IoT-enabled menggunakan berbagai communication protocols. Protokol harus lightweight dengan low-network-bandwidth functionality.

🔄
Multi-Device Communication

Mengkonfigurasi multiple device untuk mengakses IoT things bahkan remote kapan saja dan dari mana pun. Mendukung fleksibilitas IoT 3D plane.

Cloud Tier sebagai Middleware: Cloud tier harus mampu horizontal scaling (jumlah device bertambah) DAN vertical scaling (berbagai IoT solution). Inilah yang membedakan IoT platform dari sekadar server tradisional.
Bagian 07

Keamanan di Lingkungan IoT-Enabled

Mengapa keamanan IoT jauh lebih sulit dari keamanan mobile — dan strategi multi-layer untuk mengatasinya.

Karena perangkat IoT sangat beragam, keamanan perangkat bergantung pada tipe dan modelnya. Dengan minim atau tidak adekuatnya fokus manufacturer pada keamanan IoT, langkah keamanan yang digunakan sering kali tidak memadai. Oleh karena itu, organisasi harus fokus mengamankan perangkat IoT dan menangkal skenario serangan di lingkungan IoT-enabled.

Seorang penyerang menggunakan perangkat IoT yang ter-compromise sebagai entry point ke jaringan dan melakukan lateral movement attack. Contoh: smart printer yang ter-compromise dapat menginfeksi sistem dan device lain di jaringan yang sama. Router yang ter-compromise dapat menyebarkan malware ke semua device IoT yang terhubung.

7.1 Strategi Pengamanan Dasar IoT

🔑
Ubah Default Password

Password default yang dipublikasikan di internet adalah vektor serangan #1 IoT. Mirai botnet menggunakan 60+ kredensial default untuk mengkompromi jutaan device. Wajib mengganti password saat deploy pertama kali.

🚫
Disable Unused Features

Banyak IoT device mengaktifkan UPnP, Telnet, SSH, debug console by default. Setiap fitur yang aktif adalah attack surface. Nonaktifkan yang tidak digunakan — terutama UPnP di router.

⬆
Update Firmware & Apps

Patch vulnerability secara reguler. Banyak device IoT tidak pernah di-update setelah deploy — penyerang exploit CVE lama yang sudah ada patch-nya. Otomatisasi update jika memungkinkan.

✓
Apps dari Vendor Terpercaya

Untuk IoT yang bergantung pada third-party apps, gunakan hanya aplikasi legitimate dari vendor reliable. Hindari sideloading APK/executable dari sumber tidak jelas.

7.2 Mengamankan Jaringan & Router IoT

Anatom Serangan Lateral Movement via IoT Compromised Device
Gambar 9. Serangan lateral movement via IoT — satu device ter-compromise dapat menginfeksi seluruh jaringan. Mitigasi: segmentasi + firewall.

7.3 Lima Pilar Keamanan IoT

1
Fokus Manufacturer yang Kurang

Dengan tidak adekuatnya fokus manufacturer pada security, langkah keamanan sering tidak memadai. Organisasi harus memilih vendor dengan track record keamanan dan melakukan security assessment sebelum deploy.

2
Amankan Network Devices & Routers

Karena IoT device sebagai entry point, fokus pada pengamanan network devices dan routers: map & monitor semua device, segmentasi jaringan, arsitektur jaringan aman, router dengan in-built firewall, disable UPnP.

3
Multi-layered Management

Untuk mengamankan IoT device yang beragam, diperlukan overarching multi-layered security plan dan maintenance konstan. Endpoint security + network traffic monitoring + appliance-based threat detection.

4
Company-wide Collaboration

Kolaborasi & sinkronisasi seluruh perusahaan diperlukan — IT, OT, Security, Legal, HR harus align. IoT security bukan hanya masalah IT, tapi melibatkan seluruh organisasi.

5
Endpoint & Network Defense

Enforce security solutions yang safeguard IoT devices dan detect malware di endpoint level. Security software yang check network traffic antara router dan device. Network appliance yang monitor semua port & protocol.

Kasus Nyata: Botnet Mirai (2016) mengkompromi 600.000+ IoT device (CCTV, router, DVR) menggunakan 60+ kredensial default, lalu meluncurkan DDoS 1.2 Tbps ke Dyn DNS yang menjatuhkan Twitter, Netflix, Reddit. VPNFilter (2018) menginfeksi 500.000+ router dengan kemampuan firmware bricking. Pelajaran: default credentials + no segmentation = bencana skala internet.

Device Management
Memastikan transmisi data yang aman untuk interaksi halus antar perangkat dan menjamin fungsi perangkat yang tepat:
  • Identify identity of devices — pastikan trusted device dengan software genuine yang transmit reliable data.
  • Configure & control perangkat sesuai kebutuhan sistem (contoh: beri ID untuk device).
  • Monitor & diagnose untuk smooth & secure functioning.
  • Update & maintain software — tambah fungsi, fix bug, address vulnerabilities.
User Management
Memberikan kontrol atas pengguna yang mengakses sistem IoT:
  • Identifikasi pengguna, set peran (owner, guest, dll).
  • Set access levels dan kontrol akses ke informasi spesifik.
  • Set user ownership dan add/remove pengguna.
  • Manage user settings dan izin operasi tertentu (contoh: control & record user activities).
Security Monitoring
Untuk address security breach di tahap awal dan mencegah malicious attack:
  • Log & analyze commands yang dikirim control applications ke things.
  • Monitor actions of users dan simpan semua di cloud.
  • Identify patterns of malicious behavior secara proaktif.
  • Store samples of malicious activity dan bandingkan dengan log IoT system untuk avoid serangan & dampaknya.
Best Practice: Tiga pilar ini harus diintegrasikan, bukan terpisah. Device Management tanpa Security Monitoring = buta terhadap serangan. User Management tanpa Device Management = tidak tahu device mana yang melakukan apa. Integrasi adalah kunci.
Bagian 09

Prinsip Stack-wise IoT Security

Untuk solusi IoT end-to-end, keempat lapisan — Device, Communication, Cloud, dan Process — harus diamankan secara konsisten.

Banyak perangkat IoT terhubung ke jaringan dan akhirnya ke cloud, yang menyebabkan kerentanan terhadap banyak threat vector. Untuk mengembangkan solusi IoT end-to-end (E2E), lapisan device, communication, cloud, dan process harus diamankan. Berikut adalah prinsip stack-wise IoT security yang harus diimplementasikan di setiap lapisan.

9.1 Visualisasi Stack-wise Security

Stack-wise IoT Security — 4 Lapisan Pertahanan Terintegrasi
Gambar 11. Stack-wise security — setiap lapisan memiliki prinsip khusus yang harus diimplementasikan secara konsisten.

9.2 Prinsip Detail per Lapisan

①Device Layer

  • Need device intelligence untuk handle complex security tasks — most IoT devices (microprocessor) tidak mampu handle internet complexity
  • Gunakan smart devices untuk front-line duty — secure, robust, embedded security
  • Smart devices handle encryption, authentication secara native
  • Edge processing advantage: process data locally sebelum kirim cloud — eliminates forwarding large data quantity
  • Edge enhances security: process → pack → send securely
  • Memungkinkan keep sensitive information local (privacy by design)

②Communication Layer

  • Initiate connection TO cloud, NOT FROM cloud — incoming connections disallowed
  • Connection ke cloud = bi-directional channel untuk remote control
  • Gunakan lightweight message-based protocols untuk IoT device
  • Protokol harus support: double encryption, filtering, queuing, proper labeling
  • Double encryption secure client data saat pass through message switch
  • Proper labeling memastikan messages handled securely

③Cloud Layer

  • Identification, authentication, encryption for machines — bukan human
  • Human: password + occasional 2FA (password + OTP)
  • Machines: digital certificates saat akses cloud services
  • Certificates tidak hanya authenticate transactions tapi juga encrypt channel device → cloud
  • Cryptographic identification certificate tidak bisa dicapai dengan user ID + password

④Process Layer

  • Security of remote control & updates — kunci untuk IoT yang dapat di-maintain
  • Remote control: diagnostics, set new configurations, retrieve files
  • Key: incoming connections to device disallowed
  • Device harus establish secure bi-directional connection with cloud
  • Gunakan message switch sebagai communication channel
  • Secure updates = secure OTA (Over-The-Air) firmware update
Insight Penting: Prinsip stack-wise mengajarkan bahwa IoT security tidak bisa dilakukan di satu lapisan saja. Mengamankan cloud tanpa mengamankan device = sia-sia. Mengamankan communication tanpa process layer = update tidak aman. Semua lapisan harus konsisten — weakest link menentukan kekuatan keseluruhan.

Pertimbangan Keamanan IoT Framework

Empat komponen framework IoT — Edge, Gateway, Cloud Platform, dan Mobile — masing-masing dengan kebutuhan keamanan unik.

Untuk merancang perangkat IoT yang aman dan terlindungi, isu keamanan harus dipertimbangkan dengan tepat. Salah satu pertimbangan terpenting adalah pengembangan secure IoT framework untuk membangun perangkat. Idealnya, framework dirancang sedemikian rupa sehingga memberikan default security, sehingga developer tidak perlu memikirkannya kemudian.

Kriteria evaluasi keamanan untuk IoT framework dibagi menjadi empat bagian. Setiap bagian memiliki concern keamanan terkait yang dibahas dalam kriteria evaluasi masing-masing.

10.1 Visualisasi 4 Komponen IoT Framework

4 Komponen Framework IoT — Edge · Gateway · Cloud · Mobile
Gambar 12. 4 komponen IoT framework dengan masing-masing 4-5 kontrol keamanan yang harus diimplementasikan.

10.2 Detail Setiap Komponen

E
Edge

Device fisik utama yang berinteraksi dengan sekitarnya — berisi sensor, aktuator, OS, hardware, jaringan, dan kapabilitas komunikasi. Heterogeneous dan dapat di-deploy di mana saja dalam kondisi apa pun.

Framework ideal: cross-platform components untuk deployment di kondisi fisik apa pun. Pertimbangan: communication & storage encryption, no default credentials, strong passwords, latest up-to-date components.

G
Gateway

Langkah pertama edge ke Internet — menghubungkan smart device ke cloud. Communication aggregator yang memungkinkan komunikasi dengan jaringan lokal aman + koneksi aman ke jaringan publik tidak terpercaya.

Layer security untuk semua device yang terhubung. Framework ideal: strong encryption untuk secure comm antar endpoint, authentication mechanism sekuat komponen lain, multi-directional authentication, automatic updates.

C
Cloud Platform

Central aggregation & data management point. Akses harus dibatasi. Risiko lebih tinggi karena titik pusat agregasi data. Termasuk command and control (C2) component — komputer terpusat yang issue commands untuk distribusi extensions & updates.

Framework secure: encrypted communications, strong authentication credentials, secure web interface, encrypted storage, automatic updates.

M
Mobile

Mobile interface penting untuk pengumpulan & pengelolaan data. Pengguna dapat akses & interaksi dengan edge dari jauh. Beberapa apps berikan limited data dari specific edge device, lainnya allow full manipulation edge component.

Prone ke berbagai cyber-attack. Framework ideal: proper authentication mechanism, account lockout setelah failed attempts, local storage security, encrypted communication channels, security of data transmitted.

Default Security Principle: Framework IoT yang ideal memberikan default security — keamanan sudah tertanam di framework, bukan tanggungan developer belakangan. Ini mengikuti prinsip Secure by Design yang direkomendasikan oleh NIST, ENISA, dan IoT Security Foundation.

Best Practices & Panduan Keamanan IoT

12.1 Delapan Best Practices Utama

Gambar 14. 8 pilar utama best practices IoT + pilar tambahan yang harus diimplementasikan bersamaan.

12.2 Checklist Lengkap Best Practices

🔐Authentication & Access

  • Disable "guest" dan "demo" user accounts jika enabled
  • Gunakan "Lock Out" feature untuk lockout akun setelah excessive invalid login attempts
  • Implement strong authentication mechanism (MFA, certificate-based)
  • Password policy: minimal 8–10 karakter, kombinasi huruf/angka/special
  • Use CAPTCHA dan account lockout policy untuk avoid brute-force attacks
  • Allow only trusted IP addresses access device from Internet
  • Data privacy: user's account/identity harus protected & hidden dari user lain
  • Data authentication untuk confirm identity original source node

🛡Network & Encryption

  • Locate control system networks & devices behind firewalls, isolate dari business network
  • Implement IPS dan IDS in the network
  • Implement end-to-end encryption & gunakan Public Key Infrastructure (PKI)
  • Use VPN architecture untuk secure communication
  • Deploy security as unified, integrated system (silo = bahaya)
  • Disable telnet (port 23)
  • Disable UPnP port on routers
  • Maintain data confidentiality menggunakan symmetric key encryption

⚙Hardening & Maintenance

  • Protect devices against physical tampering (tamper-evident seals, secure enclosures)
  • Patch vulnerabilities & update device firmware regularly
  • Monitor traffic di port 48101 — infected devices attempt spread via port 48101
  • Verify position of mobile nodes — one physical node = one vehicle identity only
  • Use devices dari manufacturer dengan track record security awareness
  • Isolate IoT devices pada protected networks (segmentasi)

📡Monitoring & Response

  • Real-time log & analyze commands dari control applications ke things
  • Monitor & store semua user actions di cloud
  • Identify patterns of malicious behavior secara proaktif
  • Store samples of malicious activity, compare dengan logs untuk avoid serangan
  • Network appliances yang monitor semua ports & protocols untuk advanced threats
  • Security software check network traffic antara router dan connected devices
Framework Acuan: Best practices di atas sejalan dengan framework internasional: NIST IR 8259 (IoT Device Cybersecurity Capability), ENISA Baseline Security Recommendations for IoT, IoT Security Foundation Best Practice Guidelines, dan GSMA IoT Security Guidelines. Compliance ke salah satu framework ini menaikkan trust level IoT deployment signifikan.

Bagian 14 · Hands-on Lab

Modul Praktikum IoT

Empat sesi praktik hands-on: simulasi MQTT dengan Bevywise, audit keamanan perangkat IoT di rumah, analisis firmware, dan analisis traffic jaringan IoT.

14.1 Tujuan Praktikum

1
Simulasi Ekosistem IoT

Menggunakan Bevywise IoT Simulator untuk membangun ekosistem IoT virtual dengan MQTT, memahami pola komunikasi device-to-cloud dan device-to-device.

2
Audit Perangkat IoT

Melakukan audit keamanan pada perangkat IoT di rumah/kampus: identifikasi perangkat, cek default credentials, cek firmware version, cek services yang aktif.

3
Analisis Firmware

Menganalisis firmware perangkat IoT — ekstrak filesystem, identifikasi credentials hardcoded, cek vulnerability seperti default password dan backdoor.

4
Capture & Analisis Traffic

Melakukan capture dan analisis traffic jaringan IoT menggunakan Wireshark — identifikasi protokol yang digunakan, cek apakah traffic terenkripsi, deteksi anomaly.

14.2 Alat dan Bahan

💻Perangkat Keras

  • Laptop/PC dengan Wi-Fi adapter (untuk capture jaringan)
  • Optional: Raspberry Pi 4 (untuk simulasi gateway IoT)
  • Perangkat IoT rumah: smart bulb, smart plug, IP camera, smart speaker (boleh minimal 1)
  • Router Wi-Fi dengan akses admin (untuk audit konfigurasi)
  • Kabel USB (untuk ESP32/Arduino jika tersedia)

🧰Perangkat Lunak

  • Bevywise IoT Simulator (free trial) untuk simulasi MQTT
  • Wireshark untuk capture & analisis paket jaringan
  • binwalk untuk analisis firmware (extract filesystem)
  • nmap untuk scan port & services perangkat IoT
  • MQTT.fx atau MQTT Explorer untuk subscribe/publish MQTT topic
  • Fing (mobile) untuk discover perangkat di jaringan
  • Hydra (di Kali Linux) untuk test brute-force resistance
  • Python 3 + library paho-mqtt untuk skrip kustom
Catatan Hukum & Etika: Lakukan praktik HANYA pada perangkat yang Anda miliki atau punya izin tertulis. Jangan scan/audit perangkat orang lain tanpa izin — dapat melanggar UU ITE Pasal 30 & 33. Untuk firmware analisis, gunakan firmware yang publicly tersedia atau perangkat Anda sendiri.

14.3 Langkah Praktikum

Sesi 1 — Simulasi Ekosistem IoT dengan Bevywise MQTT

1
Install & Konfigurasi Bevywise IoT Simulator

Download Bevywise IoT Simulator dari bevywise.com. Extract dan jalankan server MQTT di localhost:1883. Verifikasi dengan netstat -an | grep 1883.

  • Di Linux/Mac: tar -xzf iot-simulator.tar.gz && cd iot-simulator && ./start.sh
  • Di Windows: jalankan start.bat sebagai Administrator
2
Konfigurasi Simulasi 1000 Virtual Devices

Edit conf/simulator.conf untuk membuat 1000 virtual device MQTT dengan topik sensor/temp/{device_id}, sensor/humidity/{device_id}, dan actuator/command/{device_id}. Set interval publish 5 detik, format JSON.

  • Set payload template: {"device_id":"{client_id}","ts":"{timestamp}","temp":{random(20,35)},"humidity":{random(40,80)}}
  • Upload CSV untuk dataset yang lebih realistis (opsional)
3
Subscribe & Capture dengan MQTT.fx

Buka MQTT.fx, connect ke broker localhost:1883. Subscribe ke topic sensor/temp/# (wildcard). Amati pesan yang masuk. Capture minimal 50 pesan, simpan ke file JSON untuk analisis.

4
Simulasi Device-to-Cloud Communication

Buat Python script sederhana dengan paho-mqtt yang simulate cloud consumer — subscribe ke semua topik, hitung rata-rata suhu & humidity per 30 detik, log ke file. Jalankan 5 menit, dokumentasikan output.

5
Analisis & Dokumentasi

Buat laporan: skenario yang disimulasikan, jumlah pesan/detik, latency rata-rata, observasi tentang beban jaringan. Diskusikan implikasi keamanan: apa yang terjadi jika broker tidak menggunakan TLS? Jika credential device bocor?

Sesi 2 — Audit Keamanan Perangkat IoT Rumah

1
Discover Semua Perangkat IoT di Jaringan

Install Fing di smartphone atau jalankan nmap -sn 192.168.1.0/24 di laptop. Catat: IP address, MAC address (untuk identifikasi vendor via OUI lookup), hostname. Buat tabel inventaris.

2
Port Scan & Service Identification

Untuk setiap perangkat IoT, jalankan nmap -sV -p- <ip> (atau -p 1-65535 jika lengkap). Catat: port terbuka, service, version. Perhatikan port berbahaya: 23 (Telnet), 48101 (Mirai indicator), 2323 (alternate Telnet), 7547 (TR-069/CWMP).

3
Test Default Credentials

Cari default credentials di routerpasswords.com atau defaultpassword.in. Untuk perangkat yang Anda miliki, coba login via web interface. Catat hasil: apakah default password masih aktif? Apakah ada "guest"/"demo" account?

4
Cek Firmware Version & Update Availability

Login ke admin interface setiap perangkat IoT, catat firmware version. Cek di website vendor apakah ada update. Catat tanggal release firmware yang terpasang vs yang terbaru. Perangkat dengan firmware >1 tahun = risiko tinggi.

5
Hardening & Laporan

Untuk setiap perangkat: ubah password default, disable Telnet/UPnP jika tersedia, enable auto-update, pertimbangkan pindahkan ke VLAN IoT terpisah. Buat laporan audit dengan kategori Risiko: Tinggi/Sedang/Rendah per perangkat.

Sesi 3 — Analisis Firmware dengan binwalk

1
Dapatkan Sample Firmware

Download firmware yang publicly tersedia dari vendor (banyak vendor menyediakan firmware update file untuk download). Alternatif: gunakan firmware image dari perangkat yang Anda miliki (ekstrak via JTAG/UART jika ahli). Simpan dengan ekstensi .bin atau .img.

2
Ekstrak dengan binwalk

Jalankan binwalk -e firmware.bin. Tool akan mendeteksi signature filesystem (SquashFS, JFFS2, CramFS, UbiFS) dan mengekstrak ke direktori _firmware.bin.extracted/. Jelajahi struktur direktori hasil ekstrak.

3
Cari Hardcoded Credentials

Di direktori hasil ekstrak, cari file konfigurasi: etc/passwd, etc/shadow, etc/conf, etc/config/*. Gunakan grep -ri "password\|admin\|root\|1234" etc/. Catat semua credentials yang ditemukan — ini menunjukkan risiko jika firmware bocor.

4
Identifikasi Services & Versi

Cek binary di usr/sbin/, usr/bin/, bin/. Gunakan strings binary | grep -i "version\|dropbear\|busybox\|lighttpd". Catat versi BusyBox, dropbear, web server — bandingkan dengan CVE database di cvedetails.com.

5
Laporan Kerentanan

Buat laporan: struktur firmware, credentials yang ditemukan, services & versi, CVE yang relevan. Rekomendasi mitigasi: ganti credentials, update firmware, disable service yang tidak perlu. Wajib responsible disclosure ke vendor jika menemukan kerentanan serius.

Sesi 4 — Capture & Analisis Traffic IoT dengan Wireshark

1
Setup Capture Environment

Pastikan laptop terhubung ke jaringan Wi-Fi yang sama dengan perangkat IoT. Aktifkan monitor mode di adapter Wi-Fi (jika support) atau gunakan port mirror di switch. Mulai Wireshark capture di interface yang sesuai.

2
Trigger Aktivitas IoT

Nyalakan/perikan smart bulb, trigger motion sensor IP camera, putar musik ke smart speaker. Biarkan Wireshark capture selama 5 menit. Filter: ip.addr == <ip_iot> untuk fokus pada satu perangkat.

3
Identifikasi Protokol & Endpoint

Di Wireshark, lihat Statistics → Protocol Hierarchy. Catat protokol yang digunakan: MQTT (port 1883/8883), HTTP/HTTPS, DNS, mDNS, SSDP, NTP, ARP. Identifikasi endpoint: cloud server vendor, NTP server, DNS server. Apakah ada traffic ke IP yang tidak dikenal?

4
Cek Enkripsi & Plaintext

Filter http — apakah ada traffic HTTP plaintext? Filter mqtt dan cek apakah MQTT menggunakan TLS (port 8883) atau plaintext (port 1883). Traffic plaintext = kerentanan kritis. Cek juga credentials yang terlihat di paket (right-click → Follow → TCP Stream).

5
Deteksi Anomali & Laporan

Cek: (a) traffic volume tidak biasa (potensi DDoS participation), (b) koneksi ke IP luar negeri (geo-IP lookup), (c) komunikasi yang tidak diharapkan (mis. smart bulb ngobrol dengan server iklan). Buat laporan: protokol, endpoint, status enkripsi, anomali, rekomendasi (segmentasi, firewall, VPN).

14.4 Lembar Kerja / Tugas

Jawab pertanyaan berdasarkan hasil praktikum. Setiap jawaban minimal 3-5 kalimat.

Q1
Simulasi MQTT

Dari Sesi 1, jelaskan perbedaan topik sensor/temp/# vs sensor/temp/+ dalam MQTT. Mengapa wildcard penting untuk skalabilitas IoT? Apa risiko keamanan jika broker MQTT tidak menggunakan autentikasi?

Q2
Inventaris IoT

Dari Sesi 2, sebutkan 3 perangkat IoT yang teridentifikasi. Untuk setiap perangkat, analisis: port yang terbuka, service yang berjalan, dan tingkat risiko. Manakah yang paling rentan dan mengapa?

Q3
Default Credentials

Berdasarkan Sesi 2 langkah 3, jelaskan mengapa default credentials menjadi vektor serangan #1 IoT. Hubungkan dengan kasus Mirai botnet 2016. Apa mitigasi yang harus dilakukan manufacturer dan user?

Q4
Analisis Firmware

Dari Sesi 3, credentials apa yang Anda temukan di firmware? Apa implikasinya jika seseorang mendapatkan akses ke file firmware tersebut? Bagaimana cara manufacturer seharusnya menyimpan credentials?

Q5
Traffic IoT

Berdasarkan Sesi 4, identifikasi protokol yang digunakan perangkat IoT Anda. Apakah semua traffic terenkripsi? Apa risiko traffic plaintext? Bagaimana VPN atau TLS bisa memitigasi risiko ini?

Q6
Stack-wise Security

Pilih satu perangkat IoT dari praktikum. Analisis postur keamanannya berdasarkan 4 lapisan stack-wise security (Device, Communication, Cloud, Process). Di lapisan mana perangkat ini paling lemah dan apa rekomendasinya?

14.5 Checklist Evaluasi

Praktikum dinyatakan lulus jika minimal 10 dari 12 kriteria berikut terpenuhi:

  • Bevywise IoT Simulator berjalan & menghasilkan 1000+ virtual device
  • Python script consumer berhasil subscribe & hitung rata-rata sensor
  • Inventaris minimal 5 perangkat IoT dengan tabel IP/MAC/vendor

  • Identifikasi minimal 1 perangkat dengan default credentials aktif
  • Cek firmware version minimal 3 perangkat dengan dokumentasi tanggal release

  • binwalk berhasil mengekstrak filesystem firmware
  • Temukan minimal 1 hardcoded credential di firmware
  • Identifikasi minimal 3 CVE relevan dengan services di firmware
  • Wireshark capture minimal 5 menit dengan analisis protokol
  • Identifikasi minimal 1 anomali traffic (unencrypted, IP asing, dll)
Bonus: Mahasiswa yang dapat mendemonstrasikan: (a) eksploitasi CVE spesifik di perangkat IoT yang dimiliki (dengan laporan responsible disclosure), (b) implementasi segmentasi VLAN IoT yang berhasil membatasi lateral movement, atau (c) kontribusi pertama ke IoT Security Foundation atau CVE database — akan mendapat nilai tambahan.
