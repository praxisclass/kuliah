Bagian 02

Cryptography Basics

Practice of concealing information by converting plaintext ke ciphertext.

Cryptography berasal dari Greek words kryptos (concealed, hidden) dan graphein (to write). Cryptography adalah practice of concealing information dengan converting plaintext (readable format) menjadi ciphertext (unreadable format) menggunakan key atau encryption scheme. Cryptography melindungi confidential data seperti email messages, chat sessions, web transactions, dan stored files.

Cryptography Process — Plaintext → Encrypt → Ciphertext → Decrypt → Plaintext
Gambar 2. Cryptography process — plaintext di-encrypt menjadi ciphertext, dikirim, lalu di-decrypt kembali ke plaintext.

2.1 Objectives of Cryptography

🔒
Confidentiality

Hanya pihak yang berwenang yang dapat membaca data. Tercapai via encryption — data terenkripsi tidak dapat dibaca tanpa key.

✓
Integrity

Data tidak dimodifikasi selama transit. Tercapai via hashing — perubahan kecil pada data menghasilkan hash yang berbeda.

📝
Non-repudiation

Pengirim tidak dapat menyangkal telah mengirim pesan. Tercapai via digital signatures — signature unik per pengirim.

🔑
Authentication

Verifikasi identitas pengirim. Tercapai via digital certificates dan PKI — CA memvalidasi identitas.

Bagian 03

Symmetric Encryption

Oldest cryptographic technique — same key untuk encryption dan decryption.

Symmetric encryption adalah oldest cryptographic technique untuk encrypting digital data. Symmetric encryption mensyaratkan bahwa both sender dan receiver dari message memiliki same secret key. Sender menggunakan key untuk encrypt plaintext, receiver menggunakan same key untuk decrypt ciphertext. Symmetric encryption juga dikenal sebagai secret key cryptography karena hanya menggunakan satu key.

Symmetric Encryption — Single Key untuk Encrypt & Decrypt
Gambar 3. Symmetric encryption — satu key dipakai untuk encrypt dan decrypt. Cepat, tapi key distribution menjadi tantangan.

✓Advantages

  • Fast — efficient untuk large data
  • Low overhead — less computation
  • Widely used — AES, DES, 3DES
  • Suitable untuk bulk data encryption

−Disadvantages

  • Key distribution — bagaimana share key securely?
  • Scalability — N users = N(N-1)/2 keys
  • No non-repudiation — both punya same key
  • Key compromise = all communications exposed
Bagian 04

Asymmetric Encryption

Two different keys — public key untuk encrypt, private key untuk decrypt.

Asymmetric encryption diperkenalkan untuk solving key-management problems. Asymmetric encryption menggunakan two different keys: public key (dapat dibagikan ke siapa pun) dan private key (dirahasiakan oleh owner). Pesan di-encrypt dengan public key penerima, hanya bisa di-decrypt dengan private key penerima.

Asymmetric Encryption — Public Key Encrypt, Private Key Decrypt
Gambar 4. Asymmetric encryption — public key encrypt, private key decrypt. Solves key distribution, but slower.

✓Advantages

  • No key distribution problem — public key can be shared
  • Scalable — N users = 2N keys (public + private)
  • Non-repudiation — only private key holder can decrypt/sign
  • Digital signatures — possible via reverse (private encrypt, public decrypt)

−Disadvantages

  • Slow — 1000x slower than symmetric
  • Computationally expensive — large key sizes needed
  • Not suitable for bulk data encryption
  • Key management — need PKI to verify public keys
Hybrid Approach (Best Practice): Sistem modern menggunakan keduanya: asymmetric encryption untuk securely exchange symmetric key, lalu symmetric encryption untuk encrypt actual data. Contoh: TLS/HTTPS — RSA/ECDHE untuk key exchange, AES untuk data encryption. Best of both worlds: security of asymmetric + speed of symmetric.

Bagian 06

Hashing Algorithms

One-way function yang produces fixed-length fingerprint dari arbitrary-length input.

Hash function adalah one-way mathematical function yang takes input dari arbitrary length dan produces fixed-length output (hash/digest/fingerprint). Hash tidak dapat di-reverse (one-way) — tidak bisa recover plaintext dari hash. Kegunaan: file integrity checking, password storage, digital signatures, message authentication.

4 Hash Algorithm Families — MD5, SHA-1, SHA-2, SHA-3
Gambar 6. 4 hash families — MD5 (broken), SHA-1 (deprecated), SHA-2 (current standard), SHA-3 (latest/future-proof).
Warning: MD5 dapat di-collision dalam detik menggunakan modern hardware. SHA-1 juga broken (SHAttered attack 2017). Minimum yang aman: SHA-256. Untuk password storage, gunakan bcrypt, scrypt, atau Argon2 — bukan plain SHA hash (karena SHA terlalu cepat untuk brute force).
Bagian 07

HMAC — Hash-based Message Authentication Code

Message authentication code yang uses cryptographic hash function + secret key.

HMAC (Hash-based Message Authentication Code) adalah type of message authentication code (MAC) yang uses cryptographic hash function (seperti SHA-1 atau SHA-256) bersama dengan secret key. HMAC menyediakan both integrity dan authentication — bukan hanya integrity seperti hash biasa. Strength of HMAC depends pada cryptographic strength dari underlying hash function dan size of key.

🔐
How HMAC Works

HMAC = Hash(Message + Secret Key). Sender computes HMAC dengan shared key, attaches to message. Receiver recomputes HMAC dengan same key — jika match, message authentic dan tidak tampered.

📊
HMAC Variants

HMAC-SHA1 (160-bit), HMAC-SHA256 (256-bit), HMAC-SHA512 (512-bit), HMAC-MD5 (128-bit, deprecated). Strength = min(hash strength, key size).

HMAC vs Hash: Hash biasa = integrity only (siapa pun bisa compute hash). HMAC = integrity + authentication (hanya yang punya key bisa compute). HMAC digunakan di: TLS record layer, IPsec, JWT (JSON Web Tokens), API authentication (AWS Signature v4).

Bagian 09

Public Key Infrastructure (PKI)

Security architecture untuk managing digital certificates dan public-key encryption.

Public Key Infrastructure (PKI) adalah set of hardware, software, people, policies, dan procedures yang dibutuhkan untuk create, manage, distribute, store, dan revoke digital certificates. PKI adalah security architecture yang dikembangkan untuk increasing confidence dalam electronic transactions dengan memungkinkan secure distribution dan use of public keys.

Bagian 10

Digital Signatures

Cryptographic technique untuk ensure authenticity, integrity, dan non-repudiation.

Digital signature adalah cryptographic technique yang uses asymmetric encryption untuk verify authenticity, integrity, dan non-repudiation dari digital message atau document. Digital signature dibuat dengan hashing message lalu encrypt hash dengan sender's private key. Receiver verify dengan decrypt signature menggunakan sender's public key, lalu compare dengan hash dari received message.

Bagian 11

Digital Certificates

Electronic document yang verifies identity dari certificate holder.

Digital certificate adalah electronic document yang uses digital signature to bind public key dengan identity (person, organization, device). Certificate diterbitkan oleh Certificate Authority (CA) — trusted third party yang verifies identity sebelum issue certificate. Digital certificate berisi: owner's public key, owner's identity, CA's digital signature, expiration date, serial number.

📋
Certificate Attributes

Setiap digital certificate berisi: Version (X.509 v3), Serial Number (unique per CA), Signature Algorithm (SHA-256 with RSA), Issuer (CA name), Validity (not before, not after), Subject (owner identity), Public Key (owner's public key), Extensions (key usage, SAN, etc.).

🔄
Certificate Lifecycle

(1) Application — user requests cert from CA. (2) Validation — RA verifies identity. (3) Issuance — CA signs & issues cert. (4) Usage — cert used for auth/encryption. (5) Expiration — cert expires (1-2 years). (6) Revocation — if compromised, cert revoked via CRL/OCSP.

X.509 Standard: Digital certificates mengikuti X.509 v3 standard (ITU-T). Format: DER (binary) atau PEM (Base64). File extensions: .cer, .crt, .pem, .p12 (PKCS#12, with private key), .pfx. Verify cert: openssl x509 -in cert.pem -text -noout.
Bagian 12

Certificate Authorities (CA)

Trusted entities yang issue digital certificates.

Certification Authorities (CAs) adalah trusted entities yang issue digital certificates. Digital certificate yang diterbitkan oleh CA memungkinkan verification dari identity certificate holder. Beberapa CA populer:

🔐
Comodo (Sectigo)

Menawarkan range PKI digital certificates dengan strong SSL encryption (128/256-bit). PKI management: Comodo Certificate Manager, Comodo EPKI Manager. Salah satu CA terbesar dunia.

🏦
IdenTrust

Trusted third party yang provides CA services untuk many sectors. Provides managed PKI hosting services. Trusted by financial institutions.

🌐
GoDaddy SSL

Complete range certificates yang comply dengan CA/Browser Forum guidelines. SHA-2 hash algorithm, 2048-bit RSA keys.

🆓
Let's Encrypt

Free, automated, open CA. Memprakarsai ACME protocol untuk automated certificate issuance. Certificate berlaku 90 hari (auto-renewal). Telah issue milyaran certificates — democratized HTTPS.

CA Hierarchy: Root CA (self-signed, trusted by browser) → Intermediate CA (signed by Root) → End-entity certificate (signed by Intermediate). Chain of trust: browser trusts Root → Root trusts Intermediate → Intermediate trusts End-entity. Jika salah satu broken, seluruh chain compromised.

Alur Praktikum — 4 Sesi, 20 Langkah, 1 Laporan Akhir
Gambar 9. Workflow 4 sesi praktikum Modul 10 — total 20 langkah hands-on.

13.4 Langkah Praktikum

Sesi 1 — OpenSSL Cryptography Lab

1
Symmetric Encryption dengan AES-256

Encrypt file: openssl enc -aes-256-cbc -salt -in secret.txt -out secret.enc -pbkdf2. Decrypt: openssl enc -d -aes-256-cbc -in secret.enc -out decrypted.txt -pbkdf2. Verify: diff secret.txt decrypted.txt. Catat: algoritma, key derivation (PBKDF2), salt usage.

2
Hashing & File Integrity

Generate hashes: sha256sum file.txt, md5sum file.txt, openssl dgst -sha512 file.txt. Modify 1 byte file → hash berubah total (avalanche effect). Verify integrity: sha256sum -c checksum.txt. Pelajari: collision resistance.

3
RSA Key Generation

Generate RSA keypair: openssl genrsa -out private.key 2048. Extract public key: openssl rsa -in private.key -pubout -out public.key. Examine: openssl rsa -in private.key -text -noout. Catat: modulus, publicExponent, privateExponent.

4
Asymmetric Encryption

Encrypt with public key: openssl rsautl -encrypt -inkey public.key -pubin -in message.txt -out message.enc. Decrypt with private key: openssl rsautl -decrypt -inkey private.key -in message.enc -out decrypted.txt. Compare speed: RSA encrypt 1MB file vs AES encrypt 1MB file.

5
Digital Signature dengan OpenSSL

Sign: openssl dgst -sha256 -sign private.key -out signature.sig message.txt. Verify: openssl dgst -sha256 -verify public.key -signature signature.sig message.txt. Modify message → verify fails. Laporan: semua operasi + speed comparison + security analysis.

Sesi 2 — GnuPG Email Security

1
Generate GPG Keypair

gpg --gen-key. Pilih: RSA (2048 atau 4096 bit), expiry 1-2 tahun. Isi: Real name, Email, Comment. Passphrase untuk protect private key. Verifikasi: gpg --list-keys dan gpg --list-secret-keys.

2
Encrypt & Decrypt Files

Encrypt untuk recipient: gpg -e -r <email> secret.txt → produces secret.txt.gpg. Decrypt: gpg -d secret.txt.gpg > decrypted.txt. Test: encrypt untuk diri sendiri, kirim ke partner, decrypt. Pelajari: hybrid encryption (session key + RSA).

3
Sign & Verify Messages

Sign (clearsign): gpg --clearsign message.txt → produces message.txt.asc dengan signature inline. Verify: gpg --verify message.txt.asc. Detached signature: gpg --detach-sig file.zip. Test: modify signed message → verify fails.

4
Key Exchange & Trust

Export public key: gpg --armor --export <email> > pubkey.asc. Import partner's key: gpg --import partner_pubkey.asc. Sign partner's key (web of trust): gpg --sign-key <partner_email>. Send encrypted message to partner using their imported public key.

5
Laporan GPG

Laporan: (a) keypair generation screenshot, (b) encrypt/decrypt demo, (c) sign/verify demo, (d) key exchange dengan partner, (e) comparison GPG vs S/MIME. Diskusikan: web of trust vs PKI hierarkis — mana yang lebih cocok untuk personal vs enterprise?

Sesi 3 — PKI Certificate Authority Setup

1
Create Root CA

Mkdir ~/ca dengan subdirs: certs, newcerts, private. Buat openssl.cnf untuk CA config. Generate Root CA key: openssl genrsa -out private/ca.key 4096. Self-sign Root CA cert: openssl req -new -x509 -days 3650 -key private/ca.key -out ca.crt -config openssl.cnf. Examine: openssl x509 -in ca.crt -text -noout.

2
Generate Server Certificate

Generate server key: openssl genrsa -out private/server.key 2048. Create CSR: openssl req -new -key private/server.key -out server.csr -config openssl.cnf. Sign CSR with CA: openssl ca -in server.csr -out certs/server.crt -config openssl.cnf. Verify chain: openssl verify -CAfile ca.crt certs/server.crt.

3
Setup HTTPS Server

Install nginx: apt install nginx. Config HTTPS: copy server.crt + server.key to nginx ssl dir. Edit nginx config: ssl_certificate + ssl_certificate_key. Restart nginx. Test: curl -k https://localhost (self-signed warning).

4
Install Root CA di Browser

Import ca.crt ke browser sebagai Trusted Root CA (Firefox: Preferences → Privacy → Certificates → View → Authorities → Import). Re-test: https://localhost — harus trusted (no warning). Test dengan openssl s_client -connect localhost:443 — verify certificate chain.

5
Certificate Revocation & Laporan

Revoke server cert: openssl ca -revoke certs/server.crt -config openssl.cnf. Generate CRL: openssl ca -gencrl -out crl.pem -config openssl.cnf. Config nginx untuk check CRL. Test: revoked cert harus rejected. Laporan: CA architecture, cert lifecycle, revocation process, security analysis.

Sesi 4 — Hash Analysis & Password Cracking

1
Hash Identification

Install hashid: pip install hashid. Test dengan berbagai hash: echo "5d41402abc4b2a76b9719d911017c592" | hashid → MD5. echo "09ca7e4eaa6e8ae9c7d261d129fe0834" | hashid → SHA-256. Pelajari: cara identify hash type dari format (length, charset).

2
MD5 Collision Demo

Demonstrasi MD5 collision: 2 different files dengan same MD5 hash. Download collision samples (Marc Stevens' research). md5sum file1.bin file2.bin — same hash! sha256sum file1.bin file2.bin — different SHA-256. Pelajari: mengapa MD5 tidak boleh untuk security.

3
Dictionary Attack MD5 vs bcrypt

Buat 10 password, hash dengan MD5 dan bcrypt. Crack MD5 dengan hashcat: hashcat -m 0 md5_hashes.txt rockyou.txt — harus crack dalam detik. Crack bcrypt: hashcat -m 3200 bcrypt_hashes.txt rockyou.txt — jauh lebih lambat (1000x). Laporan: time comparison.

4
Hashcat GPU (Opsional)

Jika ada GPU: hashcat -m 1000 ntlm_hashes.txt rockyou.txt -D 2 (GPU mode). Compare speed: CPU (John) vs GPU (hashcat). Benchmark: hashcat -b. Catat: hash rate per algoritma (MD5 vs SHA-256 vs bcrypt vs Argon2).

5
Laporan Hash Analysis

Laporan: (a) hash identification results, (b) MD5 collision demo, (c) crack time comparison MD5 vs bcrypt vs Argon2, (d) hashcat benchmark, (e) recommendation: bcrypt/Argon2 untuk password, SHA-256 untuk integrity. Diskusikan: mengapa plain hash tidak boleh untuk password storage.

Bagian 14

Ringkasan Modul

Rangkuman poin-poin kritis yang telah dibahas dalam Modul 10 Cryptography and PKI.

📋 Yang Telah Dipelajari

  • Cryptography basics — practice of concealing information: plaintext → encrypt → ciphertext → decrypt → plaintext. Objectives: confidentiality, integrity, non-repudiation, authentication.
  • Symmetric encryption — same key untuk encrypt & decrypt. Fast but key distribution problem. Examples: DES, AES, RC4/5/6.
  • Asymmetric encryption — two keys (public + private). Solves key distribution, enables digital signatures, but slower. Examples: RSA, DSA, Diffie-Hellman.
  • Hybrid approach — asymmetric untuk key exchange, symmetric untuk data encryption. Best of both worlds. Used in TLS/HTTPS.
  • Encryption algorithms — DES (56-bit, broken), 3DES (interim), AES (128/192/256-bit, current standard), RC4/5/6 (stream/block), RSA (public-key, 2048+ bit), DSA (signatures), Diffie-Hellman (key exchange).
  • Hashing algorithms — MD5 (128-bit, broken), SHA-1 (160-bit, deprecated), SHA-2 (256/512-bit, current standard), SHA-3 (latest, sponge construction). One-way function, collision resistance.
  • HMAC — Hash-based MAC: hash + secret key = integrity + authentication. Used in TLS, IPsec, JWT, AWS API signing.
  • Cryptography tools — OpenSSL (command line), GnuPG (PGP), hash calculators (MD5/SHA), Microsoft Crypto Tools, mobile hash apps.
  • PKI — 5 components: CA (issues certs), RA (verifies identity), Certificate Repository (storage), CRL/OCSP (revocation), Key Management. Enables secure public key distribution.
  • Digital signatures — hash message + encrypt with sender's private key. Verify: decrypt with sender's public key + compare hash. Provides authentication, integrity, non-repudiation.
  • Digital certificates — X.509 v3 format, binds public key with identity. Contains: public key, owner info, CA signature, validity, serial number. Lifecycle: application → validation → issuance → usage → expiration/revocation.
  • Certificate Authorities — Comodo/Sectigo, IdenTrust, GoDaddy, Let's Encrypt (free/automated). CA hierarchy: Root CA → Intermediate CA → End-entity. Chain of trust.
  • Praktikum 4 sesi — OpenSSL crypto lab, GnuPG email security, PKI CA setup, hash analysis & password cracking.
Key Takeaway: Cryptography adalah mathematical foundation dari semua security controls. Tanpa cryptography: tidak ada TLS/HTTPS, tidak ada VPN, tidak ada digital signatures, tidak ada secure email, tidak ada blockchain. Hybrid approach (symmetric + asymmetric) adalah backbone dari modern secure communication. PKI menyediakan trust infrastructure untuk verify identities. Pilih algoritma yang tepat: AES untuk data, RSA/ECC untuk key exchange, SHA-256 untuk integrity, bcrypt/Argon2 untuk passwords.
